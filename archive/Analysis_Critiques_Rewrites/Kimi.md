### Architectural Design

#### Content Workflow State Machine

```
draft → in_review → approved → scheduled → published → archived
  ↑       ↑           ↑          ↑          ↑
  └───────┴───────────┴──────────┴──────────┘ (can revert to draft from any state except archived)
```

#### Editorial Locking

Collaborative editing uses pessimistic locking via `HUB-02` (Cache):

-   Writer opens draft → acquires lock with 5-minute TTL.
    
-   Heartbeat extends lock every 30 seconds while editor is active.
    
-   Lock expiry releases automatically; another editor may acquire.
    
-   `HUB-06` logs every lock acquisition/release for audit trail.
    

#### Publishing Pipeline

1.  Editor triggers publish (or scheduled time reached via `HUB-24`).
    
2.  Content validated against `HUB-19` (Validation) schema.
    
3.  `HUB-14` (Search) indexes content for public search.
    
4.  `HUB-09` (Event Bus) broadcasts `ContentPublishedEvent`.
    
5.  `ESPOKE-01` (Public CMS) invalidates cache via `HUB-02`.
    
6.  `HUB-06` logs publication with before/after diff.
    

### Integration Strategy

-   `HUB-14` (Search): Content indexed at publish time; unindexed at archive time.
    
-   `HUB-11` (Cloud Storage): Media attachments stored with tenant-prefixed paths.
    
-   `ESPOKE-01` (Public CMS): Consumes published content; never writes back.
    
-   `HUB-24` (Scheduler): Drives scheduled publishing without human intervention.
