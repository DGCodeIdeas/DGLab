    11→## Component Name
    12→Database Abstraction Layer (DBAL) — `SovereignStack\Core\Database`
    13→
    14→## Description
    15→
    16→CORE-19 is the **relational database abstraction layer** for the SovereignStack Core tier. It is a thin, dependency-light wrapper over PHP's PDO extension that provides four concrete capabilities: (1) a `Connection` class that wraps a single `\PDO` instance with sensible defaults (ERRMODE_EXCEPTION, default fetch mode ASSOC, emulated prepares off, READ COMMITTED isolation), (2) a fluent `QueryBuilder` that emits parameterised SELECT / INSERT / UPDATE / DELETE statements — the only place in the stack where SQL strings are constructed, (3) a `SchemaBuilder` for DDL operations (create table, add column, create index) used by CORE-20 (Forge) migrations, and (4) a `Transaction` class that supports nested transactions via savepoints (`SAVEPOINT sp_n` / `RELEASE SAVEPOINT sp_n` / `ROLLBACK TO SAVEPOINT sp_n` — supported by MySQL and PostgreSQL).
    17→
    18→Per ADR-013, **MySQL 8.0+ (InnoDB) is the primary backend**. The DBAL also ships a PostgreSQL driver, but it is **disabled by default** and only activated at the next decision scale (see ADR-013); SQLite remains the test/dev fixture (`pdo_sqlite`). Every migration, every DDL example, and every CI fixture targets MySQL/InnoDB semantics first. MySQL-supported features (`JSON` column type with generated-column + functional indexes, `ON UPDATE CURRENT_TIMESTAMP`, `ON DUPLICATE KEY UPDATE` upsert, generated columns) are first-class; the `DriverInterface::supports(string $feature): bool` method gates engine-specific features (e.g. `jsonb`, `partial_index`, `rls`) so a caller on a driver that lacks a feature degrades gracefully or fails loud rather than crashing. This blueprint is **not** an ORM — there is no active-record base class, no model autodiscovery, no lazy-loading proxy, no UnitOfWork. Hub-tier services (HUB-04 Identity, HUB-06 Audit, HUB-19 Validation) map query results to plain PHP objects manually or via a thin `TypeMapper`; the DBAL stops at "execute parameterised SQL, return rows as associative arrays."
    19→
    20→The component exists because allowing each Hub service to call `\PDO` directly produces three predictable failure modes: (a) **SQL injection** — direct string concatenation in WHERE clauses; the QueryBuilder's "every value is a named parameter" rule makes this structurally impossible, (b) **dialect drift** — HUB-06 must avoid `RETURNING *` (a PostgreSQL-only feature) on the default MySQL driver; the SchemaBuilder and `DriverInterface` make the dialect boundary explicit, and (c) **tenant leakage** — a developer who forgets `WHERE tenant_id = ?` on a query against a multi-tenant table leaks data across tenants; the QueryBuilder auto-injects `tenant_id = :tenant_id` when a `TenantContext` is active, which is the application-level guard that *replaces* engine Row-Level Security (MySQL has no RLS; HUB-21 owns the tenant policy and CORE-19 owns the application-level guard).
    21→
    22→What this component is **not**: it is not an ORM (Doctrine ORM is a separate, heavier dependency that downstream Hubs may add if they want active-record semantics; CORE-19 stops at the DBAL layer — Doctrine DBAL was the reference, but this is minimal). It is not a migration runner (CORE-20 Forge owns migration discovery, ordering, and execution; the SchemaBuilder is its building block). It is not a multi-tenant policy engine (HUB-21 Sovereign Nexus owns RLS policies; CORE-19's tenant scoping is an application-level guard that catches the developer-error class of leakage, not a security boundary on its own). It is not a connection pool (PHP-FPM is a shared-nothing process model; pooling is per-request, and the `Connection` is a single PDO instance — persistent connections via `PDO::ATTR_PERSISTENT` are configurable but disabled by default due to connection-state leakage risk).

    36→## Architectural Design
    37→
    38→### Class Map
    39→
    40→| Class | Kind | Responsibility |
    41→|---|---|---|
    42→| `Connection` | `final class implements ConnectionInterface` | Wraps a single `\PDO` instance. Constructor takes DSN/user/password/options and forces ERRMODE_EXCEPTION, ASSOC fetch, emulated prepares off. Provides `prepare()`, `query()`, `beginTransaction()`, `commit()`, `rollBack()`, `lastInsertId()`, `exec()`, `quote()`. Tracks a transaction-depth counter for savepoint nesting. Holds a per-instance prepared-statement cache keyed by SQL hash (performance + security: a re-executed query reuses the same `PDOStatement`). |
    43→| `QueryBuilder` | `final class implements QueryBuilderInterface` | Fluent SELECT/INSERT/UPDATE/DELETE builder. Accumulates state in a `$parts` array (`select`, `from`, `where`, `orderBy`, `limit`, `offset`, `join`, `groupBy`, `having`). `execute()` builds the SQL string with named parameters (`:param_1`, `:param_2`, ...), delegates to `Connection::prepare()`, binds values, executes, returns `array<int, array<string, mixed>>`. WHERE conditions are stored as structured tuples, never concatenated as strings. Auto-injects `tenant_id = :tenant_id` when `TenantContext` is active. |
    44→| `SchemaBuilder` | `final class` | DDL builder. Methods: `createTable(string $name, \Closure $columns): self`, `addColumn(string $table, string $name, string $type, array $options = []): self`, `createIndex(string $table, array $columns, ?string $name = null, array $options = []): self`, `dropTable(string $name): self`, `execute(): int` (returns affected-row count from `Connection::exec()`). Column definitions are typed via a `ColumnDefinition` value object. Emits MySQL-first DDL; MySQL/SQLite fallbacks via `DriverInterface::supports()`. Used by CORE-20 Forge migrations; not intended for application code. |
    45→| `Transaction` | `final class` | Nested-transaction manager via savepoints. Outer `begin()` calls `Connection::beginTransaction()`; nested `begin()` calls `exec("SAVEPOINT sp_n")`. `commit()` releases the savepoint or commits the outer transaction. `rollBack()` rolls back to the savepoint or rolls back the outer transaction. Constructor takes a `ConnectionInterface`. Disposable: one `Transaction` instance per logical unit of work; not reusable after commit/rollback. |
    46→| `TypeMapper` | `final class` | PHP-type ↔ SQL-type mapper. Maps `\DateTimeInterface` → MySQL `TIMESTAMP(6)` (formatted as `Y-m-d H:i:s.u`), `\DateInterval` → `VARCHAR` (ISO8601), `bool` → `TINYINT(1)` (1/0 literals), `int` → native, `float` → native, `null` → `NULL`, `string` → native, `array`/`object` → `JSON` (encoded via `json_encode`), ULID strings → `CHAR(26)`. Bidirectional: `toSql(mixed $value): mixed` for binding, `fromSql(string $sqlType, mixed $value): mixed` for fetching (e.g., `TIMESTAMP(6)` → `\DateTimeImmutable`). |
    47→| `DriverInterface` | `interface` | Backend feature-detection contract. `getName(): string` (`'mysql'`, `'pgsql'`, `'sqlite'`), `supports(string $feature): bool` (the default MySQL driver returns true for `'json'` via generated-column + functional index, and `'upsert'` (`ON DUPLICATE KEY UPDATE`); false for `'jsonb'`, `'partial_index'`, `'rls'`, `'returning'` — the PostgreSQL driver, **disabled by default**, returns true for those when explicitly enabled). `quoteIdentifier(string $name): string`. Implementations: `MysqlDriver` (default, enabled), `PgsqlDriver` (shipped, disabled by default), `SqliteDriver`. |
    48→| `DatabaseException` | `final class extends \RuntimeException` | Marker exception for all DBAL errors. Wraps `\PDOException` with a structured message (SQL state, driver message, the offending SQL hash — never the full SQL with parameter values, to avoid leaking secrets to logs). Constructor takes `(string $message, int $code = 0, ?\Throwable $previous = null, ?string $sqlHash = null)`. |
    49→| `TenantContext` | `final class` | Immutable value object carrying the active tenant ULID. Constructed by HUB-04 (Identity) after authentication. Stored in a request-scoped service container; `QueryBuilder` checks `TenantContext::isActive()` and auto-injects `WHERE tenant_id = :tenant_id`. `null` tenant context = unscoped queries (for system tables, migrations, fixtures) — explicitly logged as unscoped. |

    51→### Interface Contracts
    52→
    53→```php
    54→<?php
    55→declare(strict_types=1);
    56→
    57→namespace SovereignStack\Core\Database;
    58→
    59→/**
    60→ * Connection contract: a thin wrapper over a single \PDO instance.
    61→ *
    62→ * Implementations MUST:
    63→ *  - Force \PDO::ATTR_ERRMODE => \PDO::ERRMODE_EXCEPTION in the constructor.
    64→ *  - Force \PDO::ATTR_DEFAULT_FETCH_MODE => \PDO::FETCH_ASSOC.
    65→ *  - Force \PDO::ATTR_EMULATE_PREPARES => false (real prepared statements;
    66→ *    emulated prepares silently allow multiple named parameters with the
    67→ *    same name, which masks application bugs and bypasses driver-level
    68→ *    type checking).
    69→ *  - Cache \PDOStatement instances per SQL string within a single
    70→ *    Connection (prepare() called twice with the same SQL returns the
    71→ *    same statement object, rebound). This is a security and performance
    72→ *    property: it makes re-execution cheap and prevents the caller from
    73→ *    holding multiple statement handles for the same SQL.
    74→ *
    75→ * Implementations MUST NOT:
    76→ *  - Re-use a \PDO instance across PHP requests (PHP-FPM shared-nothing).
    77→ *  - Expose the raw \PDO instance to callers (no getPdo() method). Callers
    78→ *    that need PDO-level operations should add a method to this interface
    79→ *    rather than reaching underneath it.
    80→ */
    81→interface ConnectionInterface
    82→{
    83→    /**
    84→     * Prepare a SQL statement for execution, with parameter binding via
    85→     * named (:name) or positional (?) parameters.
    86→     *
    87→     * @param string $sql The SQL statement. MUST use parameters for all
    88→     *     user-supplied values; implementations MUST NOT string-concatenate
    89→     *     user input into $sql. The QueryBuilder enforces this; raw
    90→     *     Connection::prepare() callers are responsible.
    91→     * @return \PDOStatement
    92→     * @throws DatabaseException On preparation failure (syntax error,
    93→     *     connection lost, driver-specific error).
    94→     */
    95→    public function prepare(string $sql): \PDOStatement;
    96→
    97→    /**
    98→     * Execute a SQL statement and return the result set.
    99→     *
   100→     * @param string $sql The SQL statement.
   101→     * @return \PDOStatement
   102→     * @throws DatabaseException On execution failure.
   103→     */
   104→    public function query(string $sql): \PDOStatement;
   105→
   106→    /**
   107→     * Execute a SQL statement with no result set (DDL, INSERT, UPDATE,
   108→     * DELETE without fetch). Returns the number of affected rows.
   109→     *
   110→     * @param string $sql
   111→     * @return int Affected row count.
   112→     * @throws DatabaseException
   113→     */
   114→    public function exec(string $sql): int;
   115→
   116→    /**
   117→     * Begin a transaction. Nested calls within the same Connection
   118→     * create a SAVEPOINT (sp_n where n is the current nesting depth).
   119→     *
   120→     * @return bool True on success.
   121→     * @throws DatabaseException If already in a transaction and the
   122→     *     backend does not support savepoints (rare).
   123→     */
   124→    public function beginTransaction(): bool;
   125→
   126→    /**
   127→     * Commit the outermost transaction or release the current savepoint.
   128→     *
   129→     * @return bool True on success.
   130→     * @throws DatabaseException If not in a transaction.
   131→     */
   132→    public function commit(): bool;
   133→
   134→    /**
   135→     * Roll back the outermost transaction or to the current savepoint.
   136→     *
   137→     * @return bool True on success.
   138→     * @throws DatabaseException If not in a transaction.
   139→     */
   140→    public function rollBack(): bool;
   141→
   142→    /**
   143→     * Return the ID of the last inserted row.
   144→     *
   145→     * @param string|null $name Sequence name (engine-specific; MySQL uses AUTO_INCREMENT or a ULID). Pass null for
   146→     *     SERIAL/IDENTITY columns.
   147→     * @return string The ID as a string (ULIDs are 26-char strings; bigint
   148→     *     IDs are stringified to avoid int overflow on 32-bit PHP).
   149→     */
   150→    public function lastInsertId(?string $name = null): string;
   151→
   152→    /**
   153→     * Quote a value for inclusion in a SQL string. SHOULD be used only
   154→     * for DDL where parameter binding is not possible (e.g., dynamic
   155→     * table names in SchemaBuilder). Application queries MUST use
   156→     * parameters via prepare() + bindValue(), never quote().
   157→     *
   158→     * @param mixed $value
   159→     * @param int $type \PDO::PARAM_* constant.
   160→     * @return string The quoted value including delimiters.
   161→     */
   162→    public function quote(mixed $value, int $type = \PDO::PARAM_STR): string;
   163→
   164→    /**
   165→     * Return the current transaction nesting depth (0 = not in a
   166→     * transaction, 1 = outermost, 2 = one savepoint, ...).
   167→     */
   168→    public function getTransactionNestingLevel(): int;
   169→}
   170→
   171→/**
   172→ * Fluent query builder contract.
   173→ *
   174→ * Every method that modifies the builder state returns $this for chaining.
   175→ * The builder is **immutable per execute() call**: execute() does not
   176→ * reset state, so the same builder can be re-executed after modifying
   177→ * state (e.g., ->limit(10)->execute() then ->limit(20)->execute()).
   178→ *
   179→ * SECURITY INVARIANT: No method on this interface accepts a raw SQL
   180→ * fragment. Every value passes through a named parameter on execute().
   181→ * Operators in where() are restricted to a known allowlist
   182→ * (=, !=, <, >, <=, >=, LIKE, ILIKE, IN, NOT IN, IS, IS NOT).
   183→ * Column names are validated against [A-Za-z_][A-Za-z0-9_]* (no
   184→ * dots, no backticks, no semicolons) — callers needing table-qualified
   185→ * columns use the table() and column() helpers, not raw strings.
   186→ */
   187→interface QueryBuilderInterface
   188→{
   189→    /**
   190→     * Set the SELECT columns. Default is ['*'].
   191→     *
   192→     * @param string ...$columns One or more column names. Validated
   193→     *     against [A-Za-z_][A-Za-z0-9_.]*.
   194→     */
   195→    public function select(string ...$columns): self;
   196→
   197→    /**
   198→     * Set the FROM table.
   199→     *
   200→     * @param string $table Table name. Validated against [A-Za-z_][A-Za-z0-9_]*.
   201→     */
   202→    public function from(string $table): self;
   203→
   204→    /**
   205→     * Add a WHERE condition joined by AND to the previous condition.
   206→     *
   207→     * @param string $column Column name. Validated.
   208→     * @param mixed $value The value to bind. Passed through TypeMapper.
   209→     * @param string $operator One of =, !=, <, >, <=, >=, LIKE, ILIKE.
   210→     *     Default '='.
   211→     */
   212→    public function where(string $column, mixed $value, string $operator = '='): self;
   213→
   214→    /**
   215→     * Add a WHERE condition joined by OR to the previous condition.
   216→     */
   217→    public function orWhere(string $column, mixed $value, string $operator = '='): self;
   218→
   219→    /**
   220→     * Add an ORDER BY clause.
   221→     *
   222→     * @param string $column Column name.
   223→     * @param string $dir 'ASC' or 'DESC'. Default 'ASC'.
   224→     */
   225→    public function orderBy(string $column, string $dir = 'ASC'): self;
   226→
   227→    /**
   228→     * Set the LIMIT.
   229→     *
   230→     * @param int $limit Must be >= 0.
   231→     */
   232→    public function limit(int $limit): self;
   233→
   234→    /**
   235→     * Set the OFFSET (requires LIMIT on most backends).
   236→     *
   237→     * @param int $offset Must be >= 0.
   238→     */
   239→    public function offset(int $offset): self;
   240→
   241→    /**
   242→     * Build the SQL, prepare, bind, execute, and return all rows.
   243→     *
   244→     * @return array<int, array<string, mixed>> List of rows, each an
   245→     *     associative array keyed by column name. Empty array if no rows.
   246→     * @throws DatabaseException On any error.
   247→     */
   248→    public function execute(): array;
   249→
   250→    /**
   251→     * Build the SQL and return it without executing. Used for debugging
   252→     * and the SQL-injection test suite (the test asserts that the built
   253→     * SQL contains the placeholder :param_n, not the literal value).
   254→     *
   255→     * @return array{sql: string, params: array<string, mixed>}
   256→     */
   257→    public function toSql(): array;
   258→}
   259→```

   261→### Reference Implementation
   262→
   263→The complete `QueryBuilder` implementation. Compiles against PHP 8.3 with `ext-pdo` only.
   264→
   265→```php
   266→<?php
   267→declare(strict_types=1);
   268→
   269→namespace SovereignStack\Core\Database;
   270→
   271→/**
   272→ * Fluent SQL query builder. Emits parameterised SELECT statements.
   273→ *
   274→ * @internal This class is the only place in SovereignStack that
   275→ *           constructs SQL strings. Application code MUST NOT
   276→ *           concatenate SQL.
   277→ */
   278→final class QueryBuilder implements QueryBuilderInterface
   279→{
   280→    /** Column-name allowlist. Dots allowed for table.column. */
   281→    private const IDENTIFIER_PATTERN = '/^[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z_][A-Za-z0-9_]*)?$/';
   282→
   283→    /** Operator allowlist. Anything else throws \InvalidArgumentException. */
   284→    private const ALLOWED_OPERATORS = [
   285→        '=', '!=', '<', '>', '<=', '>=', 'LIKE', 'ILIKE',
   286→    ];
   287→
   288→    /** @var array{select: list<string>, from: ?string, where: list<array{join: string, column: string, operator: string, param: string}>, orderBy: list<string>, limit: ?int, offset: ?int} */
   289→    private array $parts = [
   290→        'select'  => ['*'],
   291→        'from'    => null,
   292→        'where'   => [],
   293→        'orderBy' => [],
   294→        'limit'   => null,
   295→        'offset'  => null,
   296→    ];
   297→
   298→    /** @var array<string, mixed> Named parameters accumulated for execute(). */
   299→    private array $params = [];
   300→
   301→    /** Monotonic parameter counter; reset on execute(). */
   302→    private int $paramCounter = 0;
   303→
   304→    /**
   305→     * @param ConnectionInterface $connection The connection to execute against.
   306→     * @param TypeMapper $typeMapper Maps PHP values to SQL-bindable form.
   307→     * @param TenantContext|null $tenant If non-null and active, every query
   308→     *     auto-injects WHERE tenant_id = :tenant_id.
   309→     */
   310→    public function __construct(
   311→        private readonly ConnectionInterface $connection,
   312→        private readonly TypeMapper $typeMapper = new TypeMapper(),
   313→        private readonly ?TenantContext $tenant = null,
   314→    ) {}
   315→
   316→    public function select(string ...$columns): self
   317→    {
   318→        foreach ($columns as $column) {
   319→            $this->assertIdentifier($column);
   320→        }
   321→        $this->parts['select'] = $columns === [] ? ['*'] : array_values($columns);
   322→        return $this;
   323→    }
   324→
   325→    public function from(string $table): self
   326→    {
   327→        $this->assertIdentifier($table);
   328→        // Tables cannot be table.column; strip the dot allowance for table names.
   329→        if (str_contains($table, '.')) {
   330→            throw new \InvalidArgumentException("Invalid table name: {$table}");
   331→        }
   332→        $this->parts['from'] = $table;
   333→        return $this;
   334→    }
   335→
   336→    public function where(string $column, mixed $value, string $operator = '='): self
   337→    {
   338→        $this->addCondition('AND', $column, $value, $operator);
   339→        return $this;
   340→    }
   341→
   342→    public function orWhere(string $column, mixed $value, string $operator = '='): self
   343→    {
   344→        $this->addCondition('OR', $column, $value, $operator);
   345→        return $this;
   346→    }
   347→
   348→    public function orderBy(string $column, string $dir = 'ASC'): self
   349→    {
   350→        $this->assertIdentifier($column);
   351→        $dir = strtoupper($dir);
   352→        if (!in_array($dir, ['ASC', 'DESC'], true)) {
   353→            throw new \InvalidArgumentException("ORDER BY direction must be ASC or DESC, got: {$dir}");
   354→        }
   355→        $this->parts['orderBy'][] = "{$column} {$dir}";
   356→        return $this;
   357→    }
   358→
   359→    public function limit(int $limit): self
   360→    {
   361→        if ($limit < 0) {
   362→            throw new \InvalidArgumentException("LIMIT must be >= 0, got: {$limit}");
   363→        }
   364→        $this->parts['limit'] = $limit;
   365→        return $this;
   366→    }
   367→
   368→    public function offset(int $offset): self
   369→    {
   370→        if ($offset < 0) {
   371→            throw new \InvalidArgumentException("OFFSET must be >= 0, got: {$offset}");
   372→        }
   373→        $this->parts['offset'] = $offset;
   374→        return $this;
   375→    }
   376→
   377→    public function execute(): array
   378→    {
   379→        // Auto-inject tenant scoping. This is the application-level guard
   380→        // that complements the DBAL tenant scope (HUB-21); MySQL has no RLS. It
   381→        // catches developer-error queries that forget the WHERE clause;
   382→        // it is NOT a security boundary on its own.
   383→        if ($this->tenant !== null && $this->tenant->isActive()) {
   384→            $this->params[':tenant_id'] = $this->tenant->tenantId();
   385→            // Prepend tenant_id condition; do not override an explicit one.
   386→            $hasTenantCondition = false;
   387→            foreach ($this->parts['where'] as $cond) {
   388→                if ($cond['column'] === 'tenant_id' || str_ends_with($cond['column'], '.tenant_id')) {
   389→                    $hasTenantCondition = true;
   390→                    break;
   391→                }
   392→            }
   393→            if (!$hasTenantCondition) {
   394→                array_unshift(
   395→                    $this->parts['where'],
   396→                    ['join' => 'AND', 'column' => 'tenant_id', 'operator' => '=', 'param' => ':tenant_id'],
   397→                );
   398→            }
   399→        }
   400→
   401→        ['sql' => $sql, 'params' => $params] = $this->toSql();
   402→
   403→        try {
   404→            $stmt = $this->connection->prepare($sql);
   405→            foreach ($params as $name => $value) {
   406→                $stmt->bindValue($name, $value, $this->pdoType($value));
   407→            }
   408→            $stmt->execute();
   409→            return $stmt->fetchAll(\PDO::FETCH_ASSOC);
   410→        } catch (\PDOException $e) {
   411→            throw DatabaseException::fromPdoError($e, self::hashSql($sql));
   412→        } finally {
   413→            // Reset the param counter so the builder can be re-executed
   414→            // after a state mutation. Params are rebuilt on next toSql().
   415→            $this->paramCounter = 0;
   416→            $this->params = $this->tenant !== null && $this->tenant->isActive()
   417→                ? [':tenant_id' => $this->tenant->tenantId()]
   418→                : [];
   419→        }
   420→    }
   421→
   422→    public function toSql(): array
   423→    {
   424→        if ($this->parts['from'] === null) {
   425→            throw new \LogicException('Cannot build SQL: from() was not called.');
   426→        }
   427→
   428→        $sql = 'SELECT ' . implode(', ', $this->parts['select'])
   429→             . ' FROM ' . $this->parts['from'];
   430→
   431→        if ($this->parts['where'] !== []) {
   432→            $clauses = [];
   433→            foreach ($this->parts['where'] as $i => $cond) {
   434→                $param = $cond['param'];
   435→                // Allocate a fresh parameter name if not pre-allocated
   436→                // (e.g., the tenant_id condition is pre-allocated).
   437→                if ($param === '') {
   438→                    $param = $this->nextParamName();
   439→                    $this->parts['where'][$i]['param'] = $param;
   440→                    $this->params[$param] = $this->typeMapper->toSql(
   441→                        $this->parts['where'][$i]['value'] ?? null
   442→                    );
   443→                }
   444→                $joiner = $i === 0 ? '' : ' ' . $cond['join'] . ' ';
   445→                $clauses[] = $joiner . $cond['column'] . ' ' . $cond['operator'] . ' ' . $param;
   446→            }
   447→            $sql .= ' WHERE ' . implode('', $clauses);
   448→        }
   449→
   450→        if ($this->parts['orderBy'] !== []) {
   451→            $sql .= ' ORDER BY ' . implode(', ', $this->parts['orderBy']);
   452→        }
   453→
   454→        if ($this->parts['limit'] !== null) {
   455→            $sql .= ' LIMIT ' . $this->parts['limit'];
   456→        }
   457→
   458→        if ($this->parts['offset'] !== null) {
   459→            $sql .= ' OFFSET ' . $this->parts['offset'];
   460→        }
   461→
   462→        return ['sql' => $sql, 'params' => $this->params];
   463→    }
   464→
   465→    /**
   466→     * Internal: add a structured WHERE condition. Value is stored
   467→     * alongside the condition so toSql() can allocate a named parameter
   468→     * and bind the (TypeMapper-converted) value.
   469→     */
   470→    private function addCondition(string $join, string $column, mixed $value, string $operator): void
   471→    {
   472→        $this->assertIdentifier($column);
   473→        $operator = strtoupper($operator);
   474→        if (!in_array($operator, self::ALLOWED_OPERATORS, true)) {
   475→            throw new \InvalidArgumentException(
   476→                "Disallowed SQL operator: {$operator}. Allowed: " . implode(', ', self::ALLOWED_OPERATORS)
   477→            );
   478→        }
   479→        // Defer param allocation to toSql() so repeated execute() calls
   480→        // re-allocate cleanly. Value is stored here.
   481→        $this->parts['where'][] = [
   482→            'join'     => $join,
   483→            'column'   => $column,
   484→            'operator' => $operator,
   485→            'param'    => '',         // allocated by toSql()
   486→            'value'    => $value,     // consumed by toSql()
   487→        ];
   488→    }
   489→
   490→    private function nextParamName(): string
   491→    {
   492→        return ':param_' . (++$this->paramCounter);
   493→    }
   494→
   495→    private function assertIdentifier(string $identifier): void
   496→    {
   497→        if (preg_match(self::IDENTIFIER_PATTERN, $identifier) !== 1) {
   498→            throw new \InvalidArgumentException(
   499→                "Invalid SQL identifier: {$identifier}. Must match [A-Za-z_][A-Za-z0-9_.]*"
   500→            );
   501→        }
   502→    }
   503→
   504→    private function pdoType(mixed $value): int
   505→    {
   506→        return match (true) {
   507→            $value === null => \PDO::PARAM_NULL,
   508→            is_bool($value) => \PDO::PARAM_BOOL,
   509→            is_int($value)  => \PDO::PARAM_INT,
   510→            is_string($value) && strlen($value) === 26 && ulid_valid($value) => \PDO::PARAM_STR,
   511→            default         => \PDO::PARAM_STR,
   512→        };
   513→    }
   514→
   515→    private static function hashSql(string $sql): string
   516→    {
   517→        return hash('xxh3', $sql) ?: 'unknown';
   518→    }
   519→}

   606→### State Diagram
   607→
   608→The `Connection` lifecycle. PHP-FPM is shared-nothing, so the lifecycle is per-request: a Connection is constructed, enters a transaction (possibly nested via savepoints), commits or rolls back, and is closed at request shutdown. The same Connection may pass through multiple transaction cycles within one request.
   609→
   610→```mermaid
   611→stateDiagram-v2
   612→    [*] --> Constructed: new Connection(dsn)
   613→    Constructed --> Connected: PDO::__construct succeeds
   614→
   615→    Connected --> InTransaction: beginTransaction() [depth=1]
   616→    InTransaction --> InSavepoint: beginTransaction() [depth=2] → SAVEPOINT sp_1
   617→    InSavepoint --> DeeperSavepoint: beginTransaction() [depth=3] → SAVEPOINT sp_2
   618→
   619→    DeeperSavepoint --> InSavepoint: rollBack() [depth 3→2] → ROLLBACK TO SAVEPOINT sp_2
   620→    InSavepoint --> InSavepoint: commit() [depth 2→1? No: RELEASE SAVEPOINT sp_1, stay depth=1]
   621→    note right of InSavepoint
   622→        Nested commit releases the
   623→        savepoint; outer transaction
   624→        remains open (depth=1).
   625→    end note
   626→
   627→    InSavepoint --> InTransaction: commit() → RELEASE SAVEPOINT sp_1 (depth 2→1)
   628→    InTransaction --> Connected: commit() → COMMIT (depth 1→0)
   629→    InTransaction --> Connected: rollBack() → ROLLBACK (depth 1→0)
   630→
   631→    InSavepoint --> InTransaction: rollBack() → ROLLBACK TO SAVEPOINT sp_1 (depth 2→1)
   632→    DeeperSavepoint --> InSavepoint: rollBack() → ROLLBACK TO SAVEPOINT sp_2 (depth 3→2)
   633→
   634→    Connected --> InTransaction: beginTransaction() again (new outer)
   635→    Connected --> Closed: request shutdown / explicit close
   636→    InTransaction --> Closed: PANIC: rollBack forced on shutdown if still open
   637→
   638→    Closed --> [*]
   639→
   640→    note left of InTransaction
   641→        ABORTED substate:
   642→        if any nested rollBack occurs,
   643→        the outer commit() MUST throw
   644→        DatabaseException to prevent
   645→        partial-writes being persisted.
   646→    end note
   647→```

   649→## Integration Strategy
   650→
   651→**Upward (what CORE-19 consumes):**
   652→- CORE-10 (Config) provides the DSN, user, password, and driver options from environment variables and `database.json`. The factory `Connection::fromConfig(ConfigInterface $config): Connection` reads `db.dsn`, `db.user`, `db.password`, `db.options`, and `db.isolation_level` (default `READ COMMITTED`).
   653→- CORE-02 (DI Container) wires `ConnectionInterface` as a singleton per request. The container resolves `ConnectionInterface` to a single `Connection` instance; Hub services inject `ConnectionInterface` rather than constructing their own.
   654→- CORE-09 (Logging) is optional. If a `LoggerInterface` is bound, every executed query is logged at `debug` level with the SQL hash, parameter count, row count, and elapsed microseconds. **Parameter values are never logged** (PII / secret-leak risk). On `error` level, the SQL state code is logged.
   655→- CORE-03 (Event Dispatcher) receives a `QueryExecuted` event after every `execute()`, carrying the SQL hash, parameter count, row count, and elapsed time. HUB-06 (Audit Log) listens for write queries (`INSERT`/`UPDATE`/`DELETE`) and records them; HUB-15 (Health) listens for slow-query thresholds (provisional, unverified: > 100ms).
   656→
   657→**Downward (what consumes CORE-19):**
   658→- HUB-04 (Identity) — `users`, `sessions`, `password_resets` tables; uses `QueryBuilder` for all queries; depends on auto-tenant-scoping for `users` and `sessions`.
   659→- HUB-06 (Audit Log) — `audit_log` table with high write volume; uses `Connection::prepare()` directly (not `QueryBuilder`) for batch inserts; uses partial indexes (`WHERE deleted_at IS NULL`) gated on `DriverInterface::supports('partial_index')`.
   660→- HUB-01 (Config & Feature Flags) — `tenant_overrides` table with JSON column; uses `QueryBuilder::where('overrides', $payload, 'JSON_CONTAINS')` (operator mapped to MySQL `JSON_CONTAINS`; throws `DatabaseException` on the PostgreSQL driver when enabled).
   661→- HUB-19 (Validation) — `validation_rules` table with JSON column for rule definitions; same JSON pattern.
   662→- HUB-21 (Sovereign Nexus) — multi-tenant coordination; layers application-level tenant scoping (MySQL has no RLS) on top of CORE-19's application-level tenant scope (defense in depth).
   663→- CORE-20 (Forge) — uses `SchemaBuilder` for the migration scaffold; migrations are PHP files that call `$schema->createTable('users', function (ColumnDefinition $c) { ... })`.
   664→
   665→**Concrete wiring example (CORE-02 Container binding):**
   666→
   667→```php
   668→// In CORE-17 Service Provider for CORE-19:
   669→$container->singleton(ConnectionInterface::class, function (Container $c): Connection {
   670→    $config = $c->get(ConfigInterface::class);
   671→    $logger = $c->has(LoggerInterface::class) ? $c->get(LoggerInterface::class) : new NullLogger();
   672→    $connection = Connection::fromConfig($config);
   673→    $connection->setLogger($logger);
   674→    return $connection;
   675→});
   676→
   677→$container->singleton(QueryBuilderInterface::class, function (Container $c): QueryBuilder {
   678→    return new QueryBuilder(
   679→        $c->get(ConnectionInterface::class),
   680→        new TypeMapper(),
   681→        $c->get(TenantContext::class),  // null in unscoped contexts (migrations, system queries)
   682→    );
   683→});
   684→```

   697→## CI Verification Criteria
   698→
   699→- **Branch coverage: 100%** on `QueryBuilder` (`select`, `from`, `where`, `orWhere`, `orderBy`, `limit`, `offset`, `execute`, `toSql`, `addCondition`, `nextParamName`, `assertIdentifier`, `pdoType`, `hashSql`) and on `Connection` (`prepare`, `query`, `exec`, `beginTransaction`, `commit`, `rollBack`, `lastInsertId`, `quote`, `getTransactionNestingLevel`). The tenant-context branches (active / inactive / explicit-tenant-condition-already-present) must each be covered. Measured via `phpunit --coverage-html` with `xdebug` enabled in the CI matrix.
   700→- **Static analysis: phpstan level 8** with `bleedingEdge` enabled. Zero baseline-ignored errors. The `mixed` type in `where(string $column, mixed $value, ...)` is acceptable (the value flows through `TypeMapper::toSql()` which has a return type); phpstan must not flag it.
   701→- **SQL injection test:** A `@dataProvider` of 50 payloads (including `'; DROP TABLE users; --`, `' OR '1'='1`, `'; --`, `' UNION SELECT * FROM sessions --`, `"\xff\x27"` byte-sequence, `' OR ''='`, `' /* comment */`, `1; WAITFOR DELAY '0:0:5'` even though MySQL ignores it). Each payload is passed as the `email` value to `QueryBuilder::where('email', $payload)->execute()`. The test asserts (a) no exception is thrown (the payload is bound as a string literal, never executed as SQL), (b) the `users` table still exists after the test (`SELECT COUNT(*) FROM users` succeeds), (c) the returned row count is 0 (the payload does not match any email). Additional negative test: a direct attempt to inject a column-name payload via `where("email; DROP TABLE users", 'x')` throws `InvalidArgumentException` (the identifier validator rejects it).
   702→- **Transaction rollback test:** `begin() → INSERT a row → rollBack()`. After rollback, `SELECT * FROM users WHERE id = :id` returns 0 rows. The test runs on the MySQL driver (primary) and SQLite; the PostgreSQL driver is exercised only when explicitly enabled at the next decision scale.
   703→- **Nested transaction test:** `outer-begin → INSERT row A → inner-begin → INSERT row B → inner-rollBack → outer-commit`. After commit, row A exists, row B does not. Then a second test: `outer-begin → INSERT row A → inner-begin → INSERT row B → inner-commit → outer-rollBack`. After rollback, neither row exists (the inner commit only released the savepoint; the outer rollback rolled back everything).
   704→- **Type mapping test (round-trip):** Insert a row with `created_at = new \DateTimeImmutable('2026-08-04T12:34:56.789+02:00')`. Fetch the row back. Assert the fetched `created_at` (via `TypeMapper::fromSql('timestamp', $value)`) represents the same instant as the original (`$fetched->getTimestamp() === $original->getTimestamp()`) to microsecond precision. MySQL's `TIMESTAMP` normalizes to the connection's session timezone rather than preserving the original offset the way PostgreSQL's `timestamptz` does (a capability gated behind `DriverInterface::supports('timezone_offset')`, false on the default MySQL driver) — offset preservation is not asserted here, only instant-equality. Repeat with `bool` (true / false), `null`, `int`, `float`, ULID string.
   705→- **Tenant-scoping test:** With `TenantContext` active (tenantId='T1'), call `QueryBuilder::from('users')->execute()`. Assert the built SQL (via `toSql()`) contains `WHERE tenant_id = :tenant_id AND` (auto-prepended). Assert the bound `:tenant_id` equals 'T1'. Then with `TenantContext` inactive, assert no tenant_id clause is added. Then with `TenantContext` active AND an explicit `where('tenant_id', 'T2')` call, assert the explicit condition is preserved and no duplicate auto-condition is added.
   706→- **Prepared-statement cache test:** Call `Connection::prepare($sql)` twice with the same SQL. Assert the returned `\PDOStatement` is the same object instance (`spl_object_id()` matches). Call with different SQL. Assert different instances.
   707→- **Driver parity test:** The same `QueryBuilder` code (`select('id')->from('users')->where('email', 'x@y.z')->execute()`) produces a result set on MySQL 8 (InnoDB) and SQLite 3.44 (in-memory). The PostgreSQL driver is exercised only when enabled. The test asserts the SQL string differs only in dialect-specific syntax (e.g., `LIMIT 10 OFFSET 5` vs `LIMIT 5, 10` — the QueryBuilder emits the standard form, which MySQL/SQLite accept).
   708→- **Connection lifecycle test:** A `Connection` that has an open transaction at end-of-request (simulated via `register_shutdown_function`) MUST roll back automatically and log a warning. The test asserts no row was committed.

   710→## Security Properties
   711→
   712→1. **No string concatenation of user input into SQL.** The `QueryBuilder` accumulates WHERE conditions as structured tuples (`['column', 'operator', 'value']`) and only emits parameter placeholders (`:param_n`) into the SQL string. The `Connection::quote()` method exists but is annotated for DDL-only use; application queries that use `quote()` for values are flagged in code review and rejected by the CI static-analysis rule (`phpstan` custom rule forbidding `Connection::quote()` outside `SchemaBuilder`). This is the structural SQL-injection defense.
   713→2. **Operator and identifier allowlists.** The `where()` operator is validated against `['=', '!=', '<', '>', '<=', '>=', 'LIKE', 'ILIKE']`; anything else throws `InvalidArgumentException`. Column names are validated against `[A-Za-z_][A-Za-z0-9_.]*`; this prevents `where("email; DROP TABLE users", ...)` from reaching the SQL layer. The `IN` and `IS NULL` operators are handled by separate methods (`whereIn()`, `whereNull()`) not shown in the reference implementation but part of the full interface.
   714→3. **Prepared statements cached per connection.** A re-executed query reuses the same `\PDOStatement`. This is both a performance property (no re-parse) and a security property (the parameter-binding protocol is exercised consistently; there is no path where a "fast path" bypasses binding).
   715→4. **Transaction isolation level configurable; default READ COMMITTED.** Set via `Connection::setIsolationLevel(string $level)` (accepts `'READ UNCOMMITTED'`, `'READ COMMITTED'`, `'REPEATABLE READ'`, `'SERIALIZABLE'`). Default `READ COMMITTED` matches MySQL's default and is the safest level for the Sovereign Stack's workload (HUB-06 Audit Log cannot afford `SERIALIZABLE` overhead; HUB-04 Identity does not need `REPEATABLE READ`). The isolation level is set per-transaction via `SET TRANSACTION ISOLATION LEVEL ...` issued inside `beginTransaction()`; CI test asserts the level is observable via `SELECT @@transaction_isolation`.
   716→5. **Tenant scoping enforced at the QueryBuilder level.** When `TenantContext::isActive()` returns true, every query auto-prepends `WHERE tenant_id = :tenant_id` (unless an explicit `tenant_id` condition is already present). This catches the developer-error class of leakage (forgot the WHERE clause). It is **not** a security boundary on its own — a malicious caller can construct a `Connection` without a `TenantContext` and emit unscoped queries. The hard boundary is the DBAL tenant scope (MySQL has no Row-Level Security); HUB-21 owns the tenant policy that CORE-19's tenant scoping complements. Both layers must pass for a query to return cross-tenant data.
   717→6. **Parameter values never logged.** The PSR-3 logger receives the SQL hash, parameter count, row count, and elapsed time — never the parameter values themselves. This prevents PII (email addresses, password hashes — though password hashes are never queried by value) and secrets (API keys stored in HUB-01 config overrides) from leaking into log aggregators.
   718→7. **ABORTED transaction state.** If a nested transaction rolls back, the outer transaction is marked ABORTED. A subsequent `commit()` on the outer transaction throws `DatabaseException` rather than persisting partial writes. This prevents the "partial commit after inner failure" anti-pattern.

   785→## SemVer Impact
   786→
   787→**Minor** (1.0.0 initial release). The package is greenfield; there is no prior 0.x release. The 1.0.0 contract is:
   788→- `ConnectionInterface` with the 9 methods listed above
   789→- `QueryBuilderInterface` with the 9 methods listed above
   790→- The `TypeMapper`, `SchemaBuilder`, `Transaction`, `DriverInterface`, `DatabaseException`, `TenantContext` class signatures as specified
   791→- The `QueryExecuted` event payload (SQL hash, param count, row count, elapsed µs)
   792→
   793→Subsequent **minor** versions may add: `whereIn()`, `whereNull()`, `join()`, `groupBy()`, `having()`, `lockForUpdate()`, `sharedLock()`, additional `DriverInterface` implementations (e.g., `CockroachDriver`).
   794→
   795→A **major** version is required only if: (a) any method signature on `ConnectionInterface` or `QueryBuilderInterface` changes incompatibly, (b) `DatabaseException` no longer extends `\RuntimeException`, (c) the prepared-statement cache contract changes (e.g., from per-Connection to per-process), (d) tenant-scoping semantics change (e.g., from opt-out to opt-in), (e) the `QueryExecuted` event payload loses fields.
   796→
   797→The MySQL-first dialect choice (ADR-013) is **not** a SemVer-major concern: adding MySQL or SQLite support is additive (new `DriverInterface` implementations), and removing PostgreSQL support is not anticipated.
