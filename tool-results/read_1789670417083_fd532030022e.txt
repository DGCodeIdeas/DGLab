   226→   226→## §5. Tier dependency DAG & build sequence
   227→   227→
   228→   228→### §5.1 Edge-direction convention (binding)
   229→   229→
   230→   230→Every blueprint's `Dependency Status` section uses these two words with exactly these meanings — the
   231→   231→same meanings as `AUTHORING_GUIDE.md`:
   232→   232→
   233→   233→- **Upward** — the IDs **this component consumes**.
   234→   234→- **Downward** — the IDs that **consume this component**.
   235→   235→
   236→   236→A pair of components that each list the other as *Downward* is a **cycle** and a broken build, even if
   237→   237→the intent was harmless. `Verification/lint/run.php` detects mutual-downward pairs. Two such pairs
   238→   238→existed before consolidation and are fixed: `HUB-03`↔`HUB-11` and the `Upward`/`Downward` label
   239→   239→inversion inside `DEPLOY-01`'s Integration Strategy.
   240→   240→
   241→   241→**Tier order is absolute** (ADR-004): `Core → Hub → Bridge → Spoke → Deploy`. A Deploy blueprint may
   242→   242→never appear in a Core blueprint's *Upward* list; `CORE-01` is upstream of `DEPLOY-01`, never the
   243→   243→reverse.

   374→   374→

   377→   377→and is kept below for reference.
   378→   378→
   379→   379→**The effort estimates and "parallelizable" labels in the table below assume multi-person capacity and
   380→   380→are superseded.** `ADR-014` (Accepted) ratifies `Architecture/CrossCutting/SDLC-AGRD.md` as the
   381→   381→canonical methodology for the current solo-tech-lead team composition — under that model there is no
   382→   382→parallel engineering capacity, "parallelizable" steps run sequentially like everything else, and no
   383→   383→fixed week-count is trustworthy before `SDLC-AGRD.md`'s Milestone 0 produces a measured throughput

   385→   385→*durations* are not. Read the sequence, not the arithmetic.

   426→   426→## §7. Governance rules
   427→   427→
   428→   428→Binding on all contributions. `Verification/lint/run.php` enforces the mechanical subset.
   429→   429→
   430→   430→**Rule 1 — One numbering authority.** §2 is the only place a Core/Hub/Spoke/Bridge/Deploy ID's identity
   431→   431→is defined. A blueprint that changes a component's ID, name, or scope must update §2 in the same
   432→   432→commit. A blueprint and this index disagreeing is a **broken build**.
   433→   433→
   434→   434→**Rule 2 — No performance target without a method.** Every performance target must name its
   435→   435→**harness** (e.g. PHPUnit `--group performance`, `wrk`, `k6`), its **baseline** (hardware/runtime,
   436→   436→e.g. GitHub Actions `ubuntu-latest`, PHP 8.3, opcache on, Xdebug off), and its **load model**
   437→   437→(concurrency, request mix, dataset size). A target that cannot meet this bar must be written
   438→   438→**"provisional, unverified"**. Bare millisecond claims are forbidden (Finding 10).
   439→   439→
   440→   440→**Rule 3 — Evaluation docs are dated snapshots.** Any evaluation document must carry
   441→   441→`Valid as of commit <sha>. Do not use for planning without re-verification.` The archived
   442→   442→`docs/evaluation/` tree is valid as of an unknown pre-renumbering commit and must not be used
   443→   443→(Finding 2).
   444→   444→
   445→   445→**Rule 4 — Rejections need a real reason.** A `disapproved/` entry must state specifically what was
   446→   446→rejected and why. The single boilerplate line *"Varying from the original blueprints"* covering 74
   447→   447→files is insufficient (Finding 12).
   448→   448→
   449→   449→**Rule 5 — Solutions must land in the artefact, not beside it.** A weakness write-up is not resolved
   450→   450→until the referenced blueprint file is edited (Finding 11).
   451→   451→
   452→   452→**Rule 6 — Duplicate directories require a diff check.** Nothing named `*_Optimized`, `*_v2`,
   453→   453→`*_mobile`, or similar may be committed without CI verifying it is not byte-identical (or within a 5%
   454→   454→size delta) to its source (Findings 5, 18).
   455→   455→
   456→   456→**Rule 7 — Blueprint fidelity bar.** See `AUTHORING_GUIDE.md`. Placeholder and stub blueprints are
   457→   457→explicitly exempt and must say so in their first paragraph; everything else is gated.
   458→   458→
   459→   459→**Rule 8 — ADRs are required for non-obvious decisions.** Any decision with a viable alternative is
   460→   460→recorded in `ADRs/` in Nygard format before the corresponding blueprint merges (Finding 19).
   461→   461→
   462→   462→**Rule 9 — Open questions are recorded, never silently resolved.** Any fork this consolidation could
   463→   463→not close is in `OPEN-DECISIONS.md` with an owner and a decision route. Picking one silently is a
   464→   464→governance violation.
