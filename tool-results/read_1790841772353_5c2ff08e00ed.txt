    12→## Component Name
    13→Sovereign Hub Config & Flags — `SovereignStack\Hub\Config` (PSR-4 mapped to `packages/hub/config/src/` per the package's `composer.json`).
    14→
    15→## Description
    16→HUB-01 is the Hub-tier configuration authority. It extends the frozen, immutable `ConfigInterface` from CORE-10 with three runtime capabilities CORE-10 explicitly declines to provide: (1) per-tenant overrides loaded from MySQL, (2) dynamic feature flags with percentage rollouts and A/B/C variants, and (3) a bounded cache-invalidation window so that database-side changes become visible to all Hub and Spoke services within a configurable deadline (default 60 seconds). Every Hub service and every Spoke resolves both config values and feature-flag state through `GlobalConfigInterface`; consumers that bypass it and read CORE-10's `ConfigInterface` directly fail CI when they reach for keys outside the global-default namespace.
    17→
    18→The component exists because multi-tenant deployments need operator-controlled divergence from the committed baseline: tenant A may need `cache.ttl=900` while tenant B keeps the default `3600`; an operator may need to kill-switch `new_billing_flow` for everyone; a product team may need to roll out `new_ui` to 10% of users and read which variant (A, B, or C) each user sees. CORE-10 cannot do any of this — it is immutable after Kernel boot. HUB-01 layers a mutable, tenant-scoped, time-bounded view on top.
    19→
    20→What HUB-01 is **not**: not a secrets manager (HUB-20 serves rotating secrets, and any key matching `/password|secret|key|token/i` is rejected at override-write time); not a remote-config source (no Consul/etcd/AppConfig; configuration is operator-authored via SQL or a future admin tool backed by `ConfigOverrideRepository`); not a CDN-edge config layer (Bridge and External Spokes read HUB-01 through BRIDGE-01's DTO boundary, never directly). HUB-02 is the cache layer; HUB-01 is the policy and evaluation layer that *uses* HUB-02.

    30→## Architectural Design
    31→
    32→### Class Map
    33→
    34→| Class | Kind | Responsibility |
    35→|---|---|---|
    36→| `HubConfigRegistry` | `final class` | Implements `GlobalConfigInterface`. Wraps CORE-10's `ConfigInterface` (global default layer) and layers per-tenant overrides from `ConfigOverrideRepository` on top. Merged view cached in HUB-02 per tenant with tag `tenant:{id}`. |
    37→| `FeatureFlagManager` | `final class` | Implements `FeatureManagerInterface`. Loads flag definitions (cached), evaluates against `Context`, applies percentage rollout via `RolloutBucket`, returns variant for A/B/C tests. |
    38→| `Context` | `final class` (immutable) | Evaluation context: `userId`, `tenantId`, `environment` (CORE-10 `Environment` enum), plus optional `attributes` map for forward-compatible targeting rules. |
    39→| `RolloutBucket` | `final class` | Stable-hash helper. `compute(string $key): int` returns a 0–99 bucket from `xxh3($key) % 100` (falls back to `crc32b($key) % 100`). Same input → same bucket, deterministically, across processes and restarts. |
    40→| `ConfigOverrideRepository` | `final class` | DBAL-backed CRUD for `hub_config_overrides`. Validates override keys exist in the default schema before write (fail-fast). |
    41→| `FeatureFlagRepository` | `final class` | DBAL-backed CRUD for `hub_feature_flags`. Reads by `flag_key`; result cached in HUB-02 with 60s TTL and tag `config`. |
    42→| `GlobalConfigInterface` | `interface` | Contract every Hub/Spoke consumer depends on: `get()`, `feature()`. |
    43→| `FeatureManagerInterface` | `interface` | Contract for flag evaluation: `isEnabled()`, `getVariant()`. |
    44→| `UnknownFlagException` | `final class extends \RuntimeException` | Thrown by `isEnabled()` / `getVariant()` when the flag key is absent and no default is supplied. |
    45→| `InvalidOverrideKeyException` | `final class extends \RuntimeException` | Thrown by `ConfigOverrideRepository::set()` when the override key is not present in CORE-10's frozen schema (prevents shadow-config). |

    47→### Interface Contracts
    48→
    49→```php
    50→<?php
    51→declare(strict_types=1);
    52→
    53→namespace SovereignStack\Hub\Config;
    54→
    55→use SovereignStack\Core\Config\Environment;
    56→
    57→/**
    58→ * Tenant-aware, flag-aware configuration authority for the Hub and Spoke tiers.
    59→ *
    60→ * EXTENDS — does not replace — CORE-10's ConfigInterface. The global-default
    61→ * layer (frozen at Kernel boot) is always consulted first; per-tenant
    62→ * overrides are layered on top via HubConfigRegistry. Consumers that need
    63→ * only global defaults MAY depend on ConfigInterface directly; consumers
    64→ * that need tenant divergence or feature flags depend on this interface.
    65→ *
    66→ * All lookups are eventually consistent within a bounded cache-invalidation
    67→ * window (default 60s), enforced by HUB-02's tag-based invalidation — not
    68→ * by HUB-01's polling.
    69→ */
    70→interface GlobalConfigInterface
    71→{
    72→    /**
    73→     * Fetch a configuration value by dot-notation key, with optional tenant override.
    74→     *
    75→     * Resolution order:
    76→     *   1. If $tenantId is non-null and an override exists in
    77→     *      hub_config_overrides for (tenant_id, config_key), return it.
    78→     *   2. Otherwise, fall back to the CORE-10 frozen default.
    79→     *   3. If neither exists and $default is supplied, return $default.
    80→     *   4. If neither exists and $default is null, throw
    81→     *      \SovereignStack\Core\Config\ConfigNotFoundException.
    82→     *
    83→     * Security: an override key MUST exist in the CORE-10 default schema
    84→     * (enforced at write time by ConfigOverrideRepository::set()); shadow-config
    85→     * is impossible.
    86→     *
    87→     * @param string      $key      Dot-notation key, e.g. "cache.ttl".
    88→     * @param mixed       $default  Returned if neither override nor default exists. When supplied, MUST NOT throw.
    89→     * @param string|null $tenantId ULID (26 chars) of the tenant whose override applies, or null for global-only resolution.
    90→     *
    91→     * @return mixed The resolved value; type depends on the key.
    92→     *
    93→     * @throws \SovereignStack\Core\Config\ConfigNotFoundException If absent everywhere and $default is not supplied.
    94→     */
    95→    public function get(string $key, mixed $default = null, ?string $tenantId = null): mixed;
    96→
    97→    /**
    98→     * Convenience wrapper around FeatureFlagManager::isEnabled() using a Context
    99→     * derived from the current request (typically the HUB-04 principal). Returns
   100→     * false for unknown flags (never throws) — a missing flag is treated as "off",
   101→     * because kill-switch callers expect a bool.
   102→     *
   103→     * Callers that need to distinguish "off" from "unknown" MUST call
   104→     * FeatureManagerInterface::isEnabled() directly and catch UnknownFlagException.
   105→     */
   106→    public function feature(string $flag): bool;
   107→}

   109→
   110→```php
   111→<?php
   112→declare(strict_types=1);
   113→
   114→namespace SovereignStack\Hub\Config;
   115→
   116→/**
   117→ * Evaluates feature flags against an immutable Context.
   118→ *
   119→ * Flag definitions live in hub_feature_flags and are cached in HUB-02 with a
   120→ * 60s TTL and tag ['config']. Cache misses load from CORE-19 (MySQL). For
   121→ * a given Context the result is deterministic — the same user always lands on
   122→ * the same side of a rollout and always sees the same variant.
   123→ *
   124→ * Variants: when the flag's `variants` JSON column is non-null, it is decoded
   125→ * as an object mapping variant keys to percentage weights (e.g. {"A":50,"B":50}).
   126→ * getVariant() returns the variant key whose bucket range contains the user's
   127→ * stable hash. If `variants` is null, getVariant() returns "default".
   128→ */
   129→interface FeatureManagerInterface
   130→{
   131→    /**
   132→     * Whether the flag is enabled for the supplied Context.
   133→     *
   134→     * Evaluation order:
   135→     *   1. Flag disabled in DB → false (short-circuit).
   136→     *   2. enabled, rollout_percentage = 0 → false (no users).
   137→     *   3. enabled, rollout_percentage = 100 → true (all users).
   138→     *   4. enabled, 0 < rollout_percentage < 100 → true iff
   139→     *      RolloutBucket::compute($flag . ':' . $context->userId) < $percentage.
   140→     *
   141→     * If $context is null, a default Context with userId="anonymous" is used;
   142→     * percentage rollouts then resolve consistently for anonymous traffic.
   143→     *
   144→     * @throws UnknownFlagException If the flag key is unknown. Callers that prefer "off" semantics should use GlobalConfigInterface::feature().
   145→     */
   146→    public function isEnabled(string $flag, ?Context $context = null): bool;
   147→
   148→    /**
   149→     * The variant key assigned to this Context for the supplied flag.
   150→     *
   151→     * Returns "default" if the flag has no variants. Returns "off" if the flag
   152→     * is disabled or the Context's rollout bucket places it outside the enabled
   153→     * percentage — callers MUST check isEnabled() first if they need to
   154→     * distinguish "off because disabled" from "off because not in rollout".
   155→     *
   156→     * @throws UnknownFlagException If the flag key is unknown.
   157→     */
   158→    public function getVariant(string $flag, ?Context $context = null): string;
   159→}

   202→### Reference Implementation
   203→
   204→The following class is the complete, copy-pasteable `FeatureFlagManager`. It compiles against PHP 8.3 with only `ext-hash` (optional, falls back to `ext-standard`'s `crc32`). Drop it into `packages/hub/config/src/FeatureFlagManager.php`.
   205→
   206→```php
   207→<?php
   208→declare(strict_types=1);
   209→
   210→namespace SovereignStack\Hub\Config;
   211→
   212→use SovereignStack\Core\Config\Environment;
   213→use SovereignStack\Hub\Cache\CacheInterface; // HUB-02 contract
   214→use SovereignStack\Hub\Cache\CacheItem;
   215→
   216→/**
   217→ * Evaluates feature flags against an immutable Context.
   218→ *
   219→ * Caching strategy: every flag definition loaded from the DB is cached in HUB-02
   220→ * under key "hub:flag:{flag_key}" with a 60s TTL and tag ['config']. Writes to
   221→ * hub_feature_flags MUST call invalidateTags(['config']) — enforced by
   222→ * FeatureFlagRepository::save(), not by this class. Stale cache never exceeds 60s.
   223→ *
   224→ * Per-Context evaluation results are NOT cached: the percentage-rollout
   225→ * computation is O(1) (one xxh3 call + modulo) and caching per user×flag would
   226→ * explode the cache cardinality. The 60s definition cache is sufficient: a
   227→ * flag change propagates within 60s, and within that window each evaluation is
   228→ * deterministic per user.
   229→ */
   230→final class FeatureFlagManager implements FeatureManagerInterface
   231→{
   232→    private const CACHE_TTL_SECONDS = 60;
   233→    private const CACHE_TAG_CONFIG  = 'config';
   234→
   235→    public function __construct(
   236→        private readonly FeatureFlagRepository $repository,
   237→        private readonly CacheInterface $cache,
   238→    ) {
   239→    }
   240→
   241→    public function isEnabled(string $flag, ?Context $context = null): bool
   242→    {
   243→        $context ??= Context::anonymous(Environment::Production);
   244→
   245→        $definition = $this->loadDefinition($flag);
   246→        if ($definition === null) {
   247→            throw new UnknownFlagException("Unknown feature flag [{$flag}].");
   248→        }
   249→
   250→        // Short-circuit: disabled flags are off for everyone.
   251→        if (!$definition['enabled']) {
   252→            return false;
   253→        }
   254→
   255→        $percentage = $definition['rollout_percentage'];
   256→
   257→        // 0% rollout: nobody. 100% rollout: everyone (skip hash).
   258→        if ($percentage === 0) {
   259→            return false;
   260→        }
   261→        if ($percentage === 100) {
   262→            return true;
   263→        }
   264→
   265→        // Deterministic per-user bucketing.
   266→        $bucket = RolloutBucket::compute($flag . ':' . $context->userId);
   267→        return $bucket < $percentage;
   268→    }
   269→
   270→    public function getVariant(string $flag, ?Context $context = null): string
   271→    {
   272→        $context ??= Context::anonymous(Environment::Production);
   273→
   274→        $definition = $this->loadDefinition($flag);
   275→        if ($definition === null) {
   276→            throw new UnknownFlagException("Unknown feature flag [{$flag}].");
   277→        }
   278→
   279→        if (!$definition['enabled']) {
   280→            return 'off';
   281→        }
   282→
   283→        $variants = $definition['variants'];
   284→        if ($variants === null || $variants === []) {
   285→            return 'default';
   286→        }
   287→
   288→        // Variants are weights summing to 100 (validated at write time).
   289→        // Walk the cumulative distribution; the first bucket whose
   290→        // upper bound exceeds the user's stable hash wins.
   291→        $bucket = RolloutBucket::compute($flag . ':variant:' . $context->userId);
   292→        $cumulative = 0;
   293→        foreach ($variants as $variantKey => $weight) {
   294→            $cumulative += $weight;
   295→            if ($bucket < $cumulative) {
   296→                return (string) $variantKey;
   297→            }
   298→        }
   299→
   300→        // Weights did not sum to 100 (defensive — write-time validation
   301→        // rejects this). Fall back to the last variant.
   302→        return (string) array_key_last($variants);
   303→    }
   304→
   305→    /**
   306→     * Load a flag definition from cache, falling back to the DB.
   307→     * Returns null if the flag key does not exist in hub_feature_flags.
   308→     *
   309→     * @return array{
   310→     *     enabled: bool,
   311→     *     rollout_percentage: int,
   312→     *     variants: array<string,int>|null
   313→     * }|null
   314→     */
   315→    private function loadDefinition(string $flag): ?array
   316→    {
   317→        $cacheKey = 'hub:flag:' . $flag;
   318→
   319→        $cached = $this->cache->get($cacheKey);
   320→        if ($cached instanceof CacheItem && $cached->isHit()) {
   321→            /** @var array{enabled:bool,rollout_percentage:int,variants:array<string,int>|null}|null $value */
   322→            $value = $cached->get();
   323→            return $value;
   324→        }
   325→
   326→        $fromDb = $this->repository->findByKey($flag); // null if not found
   327→        $this->cache->set(
   328→            $cacheKey,
   329→            $fromDb,
   330→            self::CACHE_TTL_SECONDS,
   331→            [self::CACHE_TAG_CONFIG],
   332→        );
   333→        return $fromDb;
   334→    }
   335→}
   336→```
   337→
   338→```php
   339→<?php
   340→declare(strict_types=1);
   341→
   342→namespace SovereignStack\Hub\Config;
   343→
   344→/**
   345→ * Stable-hash helper for percentage rollouts.
   346→ *
   347→ * Determinism contract: for any string $key, compute($key) returns the same
   348→ * integer in [0, 100) across processes, requests, and restarts on the same PHP
   349→ * build. This is what makes percentage rollouts "sticky" per user — the UI does
   350→ * not flicker between requests.
   351→ *
   352→ * Hash choice: xxh3 if ext-hash exposes it (PHP 8.3+ typically does); falls
   353→ * back to crc32b. Both are pure functions, no I/O, no allocation. xxh3 is
   354→ * preferred for distribution quality at scale; crc32b is the universally-
   355→ * available floor.
   356→ */
   357→final class RolloutBucket
   358→{
   359→    /**
   360→     * @return int Integer in [0, 100). Suitable for direct comparison
   361→     *             against a rollout percentage: `compute($key) < $pct`.
   362→     */
   363→    public static function compute(string $key): int
   364→    {
   365→        $hash = function_exists('hash')
   366→            && in_array('xxh3', hash_algos(), true)
   367→            ? hash('xxh3', $key, binary: false)
   368→            : hash('crc32b', $key, binary: false);
   369→
   370→        // Take the last 8 hex chars (32 bits) and modulo 100.
   371→        return hexdec(substr($hash, -8)) % 100;
   372→    }
   373→}
   374→```

   376→### SQL DDL
   377→
   378→MySQL 8 (InnoDB) per ADR-013. The `tenants(id)` reference presumes HUB-04's `tenants` table (CHAR(26) ULID per ADR-009); HUB-01 lands after HUB-04 per Build Sequence Step 8.
   379→
   380→```sql
   381→-- Per-tenant configuration overrides.
   382→-- An override applies a different value for an EXISTING CORE-10 config key; the
   383→-- key must be present in the frozen schema (enforced at write time by
   384→-- ConfigOverrideRepository::set(), which queries the ConfigValidator schema).
   385→-- Secrets (key matching /password|secret|key|token/i) are rejected outright —
   386→-- use HUB-20 (Vault) for per-tenant secrets.
   387→CREATE TABLE hub_config_overrides (
   388→    id           BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
   389→    tenant_id    CHAR(26) CHARACTER SET ascii NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
   390→    config_key   VARCHAR(191) NOT NULL,
   391→    config_value JSON         NOT NULL,
   392→    updated_at   TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
   393→    UNIQUE (tenant_id, config_key)
   394→);
   395→
   396→CREATE INDEX idx_config_overrides_tenant ON hub_config_overrides(tenant_id);
   397→CREATE INDEX idx_config_overrides_key    ON hub_config_overrides(config_key);
   398→
   399→-- Feature flag definitions.
   400→-- rollout_percentage is the share of users (by stable hash) for whom isEnabled()
   401→-- returns true; 0 = nobody, 100 = everyone. variants is null for a binary flag,
   402→-- or a JSON object {"A": 50, "B": 50} for A/B/C tests (weights must sum to 100,
   403→-- enforced at write time).
   404→CREATE TABLE hub_feature_flags (
   405→    id                  BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
   406→    flag_key            VARCHAR(191) NOT NULL UNIQUE,
   407→    enabled             BOOLEAN      NOT NULL DEFAULT FALSE,
   408→    rollout_percentage  SMALLINT     NOT NULL DEFAULT 0
   409→                                     CHECK (rollout_percentage BETWEEN 0 AND 100),
   410→    variants            JSON,    -- {"A": 50, "B": 50} or NULL
   411→    description         TEXT,
   412→    updated_at          TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP
   413→);
   414→
   415→CREATE INDEX idx_feature_flags_enabled ON hub_feature_flags(enabled) WHERE enabled = TRUE;
   416→```

   496→## Integration Strategy
   497→
   498→**Upward wiring.** The CORE-18 Kernel constructs `HubConfigRegistry` and `FeatureFlagManager` in its boot phase, after CORE-02 is ready, after CORE-10 has produced a frozen `ConfigRepository`, after CORE-19 is connected, and after HUB-02 is bootstrapped. The Kernel binds `GlobalConfigInterface` → `HubConfigRegistry` and `FeatureManagerInterface` → `FeatureFlagManager` as singletons in CORE-02.
   499→
   500→**Downward wiring.** Hub services and Spokes consume `GlobalConfigInterface` via constructor injection (preferred, CORE-17 attribute-based). The `feature()` convenience method is the only entry point most Spokes need; Hub services that need finer control (e.g., ISPOKE-01 Admin Panel rendering a flag matrix) inject `FeatureManagerInterface` directly and pass a `Context` constructed from the HUB-04 principal.
   501→
   502→**Cache tag contract.** HUB-02 exposes `CacheInterface::set($key, $value, $ttl, array $tags)`, `get($key): CacheItem`, and `invalidateTags(array $tags)`. `FeatureFlagRepository::save()` calls `invalidateTags(['config'])` after every write; `ConfigOverrideRepository::set()` calls `invalidateTags(['config', 'tenant:{id}'])`. A write commits, the tag flush propagates via Redis Pub/Sub to all Hub instances, and the next read by any instance returns the fresh value — bounded by Pub/Sub propagation latency (typically <50 ms on a healthy cluster).
   503→
   504→```php
   505→// Example: a Hub service consuming HUB-01.
   506→namespace SovereignStack\Hub\Audit;
   507→
   508→use SovereignStack\Hub\Config\GlobalConfigInterface;
   509→use SovereignStack\Hub\Config\FeatureManagerInterface;
   510→use SovereignStack\Hub\Config\Context;
   511→
   512→final class AuditService
   513→{
   514→    public function __construct(
   515→        private readonly GlobalConfigInterface $config,
   516→        private readonly FeatureManagerInterface $flags,
   517→    ) {
   518→    }
   519→
   520→    public function retentionDays(string $tenantId): int
   521→    {
   522→        return (int) $this->config->get('audit.retention_days', 90, $tenantId);
   523→    }
   524→
   525→    public function usingStructuredLogs(Context $ctx): bool
   526→    {
   527→        return $this->flags->isEnabled('audit.structured_logs', $ctx);
   528→    }
   529→}
   530→```

   532→## Benchmark & Verification Methodology
   533→
   534→Baseline for all rows: GitHub Actions `ubuntu-latest`, PHP 8.3.0, opcache enabled, no Xdebug, Redis 7.2 over TCP loopback (matches DEPLOY-01 production topology). Harness: PHPUnit `--group performance` with `microtime(true)` wall-clock. Iterations: 10 000 (1 000-iteration warm-up). All absolute targets marked **provisional, unverified** until the first CI run records a real number; subsequent runs assert ≥80% of the recorded baseline. Governance Rule 2 forbids bare ms targets without methodology — this table is the methodology.

   536→| Target | Load model | Assert |
   537→|---|---|---|
   538→| `isEnabled()` cached path | 1 flag definition pre-cached; 10 000 calls with 1 000 distinct userIds (rollout_percentage=50); measure wall-clock per call | **provisional, unverified** — the approved `< 0.005ms` target is retained as a ceiling hypothesis, not an assertion. First CI run records the real median; subsequent runs assert median ≤ recorded baseline × 1.25. O(1) in user count (no per-user cache lookup). |
   539→| `isEnabled()` cache-miss path | Cache flushed between every call; 1 000 calls; measure wall-clock including DB round-trip | **provisional, unverified** — dominated by MySQL round-trip (~0.3–1.0 ms loopback); assert cache-miss ≤ 100× cached path. |
   540→| `getVariant()` cached path | 3-variant flag (50/30/20); 10 000 calls with 1 000 distinct userIds | **provisional, unverified** — within 1.5× of `isEnabled()` cached path. |
   541→| `RolloutBucket::compute()` | 1 000 000 distinct keys; xxh3 and crc32b measured separately | **provisional, unverified** — both O(1); xxh3 ≥ 2× faster than crc32b expected, not asserted. |

   547→## CI Verification Criteria
   548→
   549→- **Branch coverage:** 100% on `FeatureFlagManager::isEnabled()` and `getVariant()` (all six return paths: unknown flag, disabled, 0%, 100%, percentage-bucket true, percentage-bucket false); 100% on `RolloutBucket::compute()` (xxh3 branch and crc32b branch); 95% on `HubConfigRegistry::get()`.
   550→- **Static analysis:** `phpstan.neon` level 8, zero baseline-ignored errors; `phpstan/strict-rules` enabled; `treatPhpDocTypesAsCertain: true`. Custom PHPStan rule rejects any `$_ENV` / `$_SERVER` reference outside `SovereignStack\Core\Config\ConfigLoader` (inherited from CORE-10's CI).
   551→- **Cross-tenant isolation test (`CrossTenantIsolationTest`):** set override `cache.ttl=900` for tenant A; assert `get('cache.ttl', null, 'tenantA') === 900`; assert `get('cache.ttl', null, 'tenantB') === 3600`; assert `get('cache.ttl') === 3600`. Repeat after flushing HUB-02 for tenant A only — tenant B's view is unchanged.
   552→- **Percentage-rollout stability test (`PercentageRolloutStabilityTest`):** for a flag at 50% rollout, evaluate `isEnabled()` 1 000 times for the same `Context`; assert all 1 000 return the same value. Repeat for 50 distinct userIds. Then restart the PHP process (fresh `FeatureFlagManager`) and re-evaluate; assert identical results (deterministic across processes).
   553→- **Cache-invalidation test (`CacheInvalidationTest`):** load a flag (cache populated); assert `isEnabled('test')` returns false; update DB to `enabled=true, rollout_percentage=100` via `FeatureFlagRepository::save()`; assert `isEnabled('test')` returns true within one cache-read after the save (tag invalidation flushes).
   554→- **Override-key validation test (`OverrideKeyValidationTest`):** attempt `set(tenant, 'nonexistent.key', 'value')`; assert `InvalidOverrideKeyException`. Attempt `set(tenant, 'database.password', 'value')` (secret pattern); assert `InvalidOverrideKeyException`. Both rejected at write time — fail-fast.
   555→- **Variants-weight validation test:** attempt to save a flag with `variants={"A":60,"B":30}` (sums to 90); assert rejection. Sum to 100 — accepted.
   556→- **Uniformity test (from benchmark table):** 100 000 userIds at 50% rollout; `true` count in [49 500, 50 500]. Same at 10% / 25% / 75% / 90%.

   558→## Security Properties
   559→
   560→1. **Tenant overrides never leak into the global default pool.** Enforced at read time: `HubConfigRegistry::get($key, $default, $tenantId)` consults the override row only when `$tenantId` is non-null; a `get($key)` call with no tenant argument resolves exclusively against CORE-10's frozen repository. CI: `CrossTenantIsolationTest`. The global pool is read-only by construction (CORE-10 immutability invariant).
   561→2. **Override keys must exist in the default schema.** Enforced at write time by `ConfigOverrideRepository::set()`: queries CORE-10's `ConfigValidator` schema for the supplied key and throws `InvalidOverrideKeyException` if absent. Shadow-config is impossible — an operator cannot introduce `cache.secret_backdoor_ttl` and have it silently take effect.
   562→3. **Secrets cannot be overridden.** Any override key matching `/password|secret|key|token/i` is rejected at write time. Per-tenant secrets are HUB-20's responsibility; HUB-01 declines to store them in `hub_config_overrides.config_value` (unencrypted JSON).
   563→4. **Percentage rollout is deterministic per user.** `RolloutBucket::compute($flag . ':' . $userId)` is a pure function of a stable hash; the same user always lands on the same side of a rollout and always sees the same variant. CI: `PercentageRolloutStabilityTest`. This prevents UI flicker — a user either always sees the new UI or never does, until the operator raises the percentage past their bucket.
   564→5. **Flag changes are observable within a bounded cache-invalidation window.** The window is the lesser of (a) the 60s TTL on `hub:flag:{key}` cache entries and (b) the Redis Pub/Sub propagation latency of `invalidateTags(['config'])` called by `FeatureFlagRepository::save()`. CI: `CacheInvalidationTest` asserts ≤ 5s in CI; HUB-15 alerts if production propagation exceeds 30s (half the 60s SLO, allowing investigation before customer-visible drift).
   565→6. **Unknown flags fail closed (kill-switch semantics).** `GlobalConfigInterface::feature()` returns false for unknown flags rather than throwing — a caller checking `feature('payments.new_flow')` before the flag is defined gets a safe "off" rather than a 500. Callers that need to distinguish "off" from "unknown" use `FeatureManagerInterface::isEnabled()` and catch `UnknownFlagException`.

   567→## Migration Notes
   568→
   569→**Landing the component:**
   570→1. Create `packages/hub/config/` with `composer.json` (runtime: `php: ^8.3`, `ext-json: *`, `ext-hash: *`; require `sovereignstack/core-config`, `sovereignstack/core-dbal`, `sovereignstack/hub-cache`; dev: `phpunit/phpunit`, `phpstan/phpstan`, `friendsofphp/php-cs-fixer`), `src/`, `tests/`.
   571→2. Add to root `composer.json` `repositories` (path repository) and `require` (`"sovereignstack/hub-config": "@dev"`); `composer update sovereignstack/hub-config`.
   572→3. Apply the DDL above via CORE-19's migration runner (forward-only; HUB-04's `tenants` table must already exist).
   573→4. In CORE-18 boot phase, after CORE-10 and HUB-02 are constructed: instantiate `ConfigOverrideRepository` and `FeatureFlagRepository` (CORE-19 connections), instantiate `HubConfigRegistry` and `FeatureFlagManager`, bind both into CORE-02 as singletons.
   574→5. Roll out consumers one at a time: each Hub service currently depending on `ConfigInterface` is migrated to `GlobalConfigInterface` where it needs tenant divergence or feature flags. Pure-global-default consumers stay on `ConfigInterface`. Each migration is a separate PR.
   575→6. Seed the first flag `flag_key='hub.config_self_test', enabled=true, rollout_percentage=100`; CI smoke test asserts `feature('hub.config_self_test') === true` after Kernel boot.
   576→
   577→**Rollback:**
   578→- `git revert` the merge commit; remove from root `composer.json` `repositories` and `require`; `composer update`.
   579→- Reverse the DDL: `DROP TABLE hub_feature_flags; DROP TABLE hub_config_overrides;` (CORE-19 down-migration).
   580→- Consumers revert to CORE-10's `ConfigInterface` directly — they lose tenant overrides and feature flags but retain the frozen global default. A flag-gated feature becomes always-on or always-off depending on consumer choice (recommended: default to "off" so rollback does not surprise operators with newly-enabled features). Document this fallback in each consumer's blueprint.
   581→- No CORE-19 schema outside HUB-01's two tables is affected; no HUB-02 cache keys outside `hub:flag:*` and `hub:config:*` namespaces are touched.
   582→
   583→**Forward-compatibility note:** `Context::$attributes` is reserved for a v2 rule engine (region/segment targeting, userId allow-list/deny-list). v1 `FeatureFlagManager` ignores it; v2 adds a `RuleEvaluator` that consumes it before the percentage check. Adding `RuleEvaluator` is a Minor bump (the `FeatureManagerInterface` signature is unchanged; only `isEnabled()` semantics extend).
