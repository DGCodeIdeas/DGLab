  1066→## §7. Blind-Spot Report — What A3 Discovered That Was Not Known Before A3 Began
  1067→
  1068→This section is the A3 auditor's self-critical reflection, per the BLIND-SPOT-DOCTRINE.md §5 "What Haven't We Asked?" exercise.
  1069→
  1070→### What we discovered during A3 (this audit) that we did not know before A3 began
  1071→
  1072→1. **A1 introduced a wider propagation debt than the worklog suggested.** The worklog (line 1616-1623) says A1 was "complete" with HUB-32.md + ESPOKE-19.md published, lint extended, INDEX updated. But A3 discovered that A1's propagation was incomplete in 7+ documents: ADR-021 §13/§14/Relationship table (S-055), HUB-DECLARED-DAG (S-059), HUB-VERIFIED-DAG (S-059), CORE-CAPABILITY-DAG (S-060), HUB-EDGE-INVENTORY (S-060 evidence), INDEX §4 (S-068), Architecture/README.md (S-067). The original A1 self-assessment was too narrow.
  1073→
  1074→2. **The SHORTCOMINGS-REGISTER was never updated despite the closure rule being authored.** A3 discovered that all 47 findings in the register still say "Disposition: Open" with empty Closure evidence — including the 5 that A1/A2 actually addressed (S-001, S-002, S-033, S-003, S-004). This is S-064 — a meta-finding about the integrity-gate process itself. The closure rule (lines 22–31 of the register) was authored but never applied. Before A3, we assumed the register tracked reality; A3 shows it doesn't.
  1075→
  1076→3. **The architecture-fitness naming-drift script has a silent bug (S-074).** Before A3, we believed FF-02 (naming-drift) was a trustworthy fitness function with 0 violations. A3 discovered the script's canonical mapping for HUB-30 is wrong (it points to HUB-01's package) and the script "passes" only by coincidence. The script's 17-component coverage also hides most of the canonical blueprints (S-075). Before A3, we trusted the green CI check; A3 shows the check has structural gaps.
  1077→
  1078→4. **The lint's checkStructure has an asymmetric coverage gap (S-061).** Before A3, we believed the lint enforced all canonical blueprint files exist. A3 discovered that `validIds` was extended (HUB range 1–32) but `checkStructure` was NOT (still range 1–30 for HUB, 1–18 for ESPOKE). So the lint accepts HUB-32 references but doesn't enforce HUB-32.md exists. A silent coverage gap.
  1079→
  1080→5. **HUB-32.md and ESPOKE-19.md disagree on ISPOKE-E11/E12 identity (S-062).** Before A3, we believed the two canonical blueprints published by A1 were cross-consistent. A3 discovered they use different names for the same conceptual IDs. This is a fresh-architect trap: implementing one blueprint's consumer list produces different components than implementing the other's.
  1081→
  1082→6. **ADR-017's Provenance does not reflect A2 (S-070).** Before A3, we believed ADR-017 was an accurate record of the Fiber runtime's history. A3 discovered that A2 added a new WeakMap (`$pulseDefinitions`) but ADR-017's Provenance wasn't updated. A reader of ADR-017 would conclude the original 2026-08-23 WeakMap was sufficient — missing that A2's WeakMap was a structural fix.
  1083→
  1084→7. **The "H05/H07 Rate Limiter duplication" claim (S-025) was already known to be wrong — but it has not been remediated.** This is a carry-forward from the original audit. A3 confirms it's still wrong (HUB-05 is RBAC, not Rate Limiter). The original audit's 47 findings included this; A3 confirms it remains Open.
  1085→
  1086→8. **The CORE-02 blueprint's embedded reference implementation is still older than the live source (S-058).** The A0 worklog (line 1519) flagged this drift. A2-prep (PR #295) updated the interface docblock but NOT the embedded Container class. A3 confirms the drift is still present post-A2.
  1087→
  1088→9. **Architecture/README.md (the architecture-dir README, distinct from root README) is severely stale (S-067).** Before A3, the audit focused on root README.md (findings S-005..S-008) and INDEX.md (S-012..S-014). A3 discovered that `Architecture/README.md` is ALSO stale — it still says "30 Hub-tier blueprints" and "10 Accepted ADRs" — and it was missed by the original audit. This is a new file not in the original 47-finding register.
  1089→
  1090→10. **The original audit's S-023 finding incorrectly stated "§16 of ADR-021 doesn't actually exist".** A3 confirms §16 DOES exist (at line 275). The original S-023 had a factual error in its description. The underlying observation (the lint rule isn't implemented) is correct — captured in new finding S-056. This is a meta-finding: the original audit had its own blind spot.
  1091→
  1092→11. **The A3-RUNTIME-76 parallel audit (lens: runtime/concurrency) caught a critical gap this audit missed.** A3-RUNTIME-76's S-054 finding — that the required `packages/core/container/tests/Unit/PulseFiberIsolationTest.php` file does not exist — means S-003/S-004 are Fixed-but-not-Closed. This audit initially concluded "S-003/S-004 Closed" before reading the runtime audit's report. The triple-lens A3 process (architecture/governance + runtime + DAG) caught what a single-lens A3 would have missed. This validates the BLIND-SPOT-DOCTRINE §2 "Multiple Independent Auditors with Different Lenses" principle.
  1093→
  1094→12. **The A3-RUNTIME-76 S-048 finding (class-string pulse silent misroute) is a HIGH-severity latent defect that the architecture/governance lens did not surface.** A3-RUNTIME-76 traced the implementation step-by-step and found that `pulse()` with class-string concrete values silently misroutes or fails (interface→NotFoundException, non-self class→wrong class autowired, competing singleton→singleton wins). The architecture/governance lens did not catch this because it didn't trace the implementation's runtime behavior in detail. The runtime lens did. This is a second example of the multi-lens principle working.
  1095→
  1096→### What we did not discover during A3 (acknowledged limitations)
  1097→
  1098→- **Runtime-only issues.** A3 was static-analysis only (no PHP runtime in sandbox). The Container's `pulse()` fix (A2) was verified by code reading + PR #301 commit message, NOT by re-running the WorkerContaminationTest. PHP-runtime issues that only manifest under specific concurrency patterns remain unverified — except those caught by the parallel A3-RUNTIME-76 agent (S-048..S-054).
  1099→- **Cross-tier drift that requires running integration tests.** A3 read the DAGs and blueprints but did not run any Hub→Core integration test. The Hub DAGs' 76 declared Hub→Hub edges (post-resolution) were not verified against actual Hub code (which doesn't exist for 27 of 29 active Hubs).
  1100→- **Property-based verification of Fiber isolation.** A3 did not generate random Fiber interleaving scenarios to test the new $pulseDefinitions WeakMap. The 6 new regression tests added by A2 (per the commit message) cover specific scenarios; property-based verification would be stronger. The parallel A3-RUNTIME-76 agent's S-048 finding confirms that class-string pulse bindings (a scenario no test exercises) are broken — a property-based verifier would have caught this earlier.
  1101→
  1102→These limitations are explicit blind spots in this A3 audit. The parallel A3-RUNTIME-76 agent closed some of them (S-048..S-054). The remaining gaps should be closed by a runtime-verification subagent in a future audit cycle.
