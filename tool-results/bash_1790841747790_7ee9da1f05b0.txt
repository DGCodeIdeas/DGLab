   568→## §7. Step 7 — Honest gaps

   570→### Gap 1 — HUB-06 → HUB-11 labelled "Queue" — internal blueprint contradiction
   571→
   572→`Architecture/Hub/HUB-06.md` line 40 declares in Upward: "`HUB-11` (Queue) — optional async write path for non-critical events (see Integration Strategy)."
   573→
   574→Per `INDEX.md` §2.2 (canonical Hub map), **HUB-11 = Sovereign Cloud Storage** (NOT Queue). **HUB-10 = Sovereign Queue**.
   575→
   576→The label "Queue" attached to HUB-11 is internally contradictory — either:
   577→- (a) the target should be HUB-10 (Queue) — but HUB-10 was superseded (relocated to Runtime as RUNTIME-03 per ADR-021 §12), so the declared edge would point to a now-superseded Hub
   578→- (b) the descriptor "Queue" is wrong and the target HUB-11 (Cloud Storage) is the actual intent — but this is semantically odd for "optional async write path for non-critical events" (which is a queue pattern, not cloud-storage)
   579→
   580→**Recorded as:** Row 16 in §5.1 — `HUB-06 → HUB-11`, DECLARED_ONLY, evidence `HUB-06.md line 40`, with note about the label-vs-INDEX contradiction.
   581→
   582→**Phase 2 recommendation:** Determine whether the actual intent was HUB-10 (Queue, now RUNTIME-03) or HUB-11 (Cloud Storage). If the former, the edge should be re-expressed as `HUB-06 → RUNTIME-03` (Hub → Runtime tier, INTEGRATION edge type) and removed from the Hub DAG. If the latter, the descriptor "Queue" should be corrected to "Cloud Storage" in the blueprint.
   583→
   584→### Gap 2 — 11 declared edges point to superseded HUB-10 (8) and HUB-25 (3)

   591→
   592→**Phase 2 recommendation:** These should be reinterpreted as Hub → Runtime tier INTEGRATION edges (`HUB-XX → RUNTIME-03` or `RUNTIME-04`), and removed from the Hub-tier DAG. These are inter-tier edges and belong in either (a) the Runtime-tier DAG as incoming edges, or (b) a separate cross-tier integration inventory. ADR-021 doesn't explicitly resolve which DAG owns these — that's a Phase 2 governance decision.

   594→### Gap 3 — HUB-15's "reverse Downward" list — semantic-direction inconsistency
   595→
   596→`Architecture/Hub/HUB-15.md` line 90 contains within its **Downward** section:
