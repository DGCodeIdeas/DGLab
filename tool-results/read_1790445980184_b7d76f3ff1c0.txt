    11→## Component Name
    12→Sovereign Guard (Validation) — `SovereignStack\Hub\Validation`
    13→
    14→## Description
    15→
    16→HUB-19 is the **declarative validation engine** for the SovereignStack Hub tier. It sits between the HTTP middleware pipeline (CORE-05) and application controllers, providing a single auditable way to assert "the body of this request matches the shape my controller expects". Every Hub service and Spoke that accepts a request body — HUB-01, HUB-04, HUB-08, HUB-17, BRIDGE-01, all 25 Internal and 15 External Spokes — funnels inbound data through `Validator::validate()` before any business logic runs. The component is the *defence-in-depth choke point* mandated by the threat model: nothing reaches a controller, a database write, or a templating engine unless it has first passed a declared rule set.
    17→
    18→The component exists because PHP's loose typing, `filter_var`'s uneven API, and the historical pattern of "validate inline at the top of each controller" together produce three failure modes this stack will not ship: (1) **inconsistent validation** — the same field is validated with different rules in different controllers, so an attacker probes for the weakest path; (2) **error-message leakage** — controllers echo `users.email column cannot be NULL` back to the client, exposing internal schema; (3) **uneven DB-touching rules** — ad-hoc uniqueness checks are written by hand per controller, sometimes via string concatenation, opening SQL injection at the validation layer. HUB-19's `RuleInterface` + declarative rule strings (`'email' => 'required|email|unique:users,email'`) collapse all three into one auditable surface: every rule is a class, every rule accepts the full input array (so cross-field rules are first-class), every DB-touching rule goes through CORE-19's parameterised query API, and every error message is a static template filled with the *field name* never the *column name*.
    19→
    20→What this component is **not**: it is not a sanitiser. The stale approved blueprint conflated validation and sanitisation under a single `GuardInterface` with a `sanitize()` method; HUB-19 drops sanitisation entirely — *validate on input, escape on output* is the rule, and output-context escaping belongs to CORE-11/CORE-12 (SuperPHP) and the CORE-04/CORE-05 response emitter. HUB-19 is also not a JSON-Schema engine; the `SchemaValidator` here is a thin convenience wrapper for the common OpenAPI request-body case, not a full draft-2020-12 implementation.
    21→

    37→## Architectural Design
    38→
    39→### Class Map
    40→
    41→| Class | Kind | Responsibility |
    42→|---|---|---|
    43→| `Validator` | `final class implements ValidatorInterface` | Main entry point. Holds optional CORE-19 `ConnectionInterface` (for DB rules) and `LoggerInterface`. `validate(array $data, array $rules): ValidationResult` iterates each field's rule list, builds a `RuleSet`, executes in declaration order, short-circuits on a failed `RequiredRule` (so a missing field does not cascade into "must be email"/"must be ≥ 8 chars"), collects `ValidationError` value objects, and returns. Never throws on invalid data — the caller decides whether to call `$result->throw()`. |
    44→| `Rule` | `abstract class implements RuleInterface` | Base class. Provides `protected readonly` storage for the message template, the `message(): string` implementation (returns the template, interpolated by the Validator), and `__toString()` for diagnostics. Subclasses implement `passes(mixed $value, array $data): bool`. |
    45→| `RuleSet` | `final class` | Immutable collection of `RuleInterface` for a single field. `execute(mixed $value, array $data): array` returns a list of `ValidationError` (empty if all pass). Enforces short-circuit on failed `RequiredRule`. |
    46→| `ValidationError` | `final class` (value object) | Immutable DTO: `field` (dot-path), `rule` (class short name), `message` (translated). `jsonSerialize()` for 422 body. No schema leakage — message uses the field name declared by the caller, never the column name. |
    47→| `ValidationResult` | `final class` | Collects `ValidationError`. `isValid()`, `errors()`, `errorsFor(string $field)`, `toArray()` (groups by field), `throw(): never` (throws `ValidationException($this)` if invalid, else returns). |
    48→| `SchemaValidator` | `final class` | Adapter converting a JSON-Schema-shaped array into native rule format, delegates to `Validator::validate()`. Subset of draft-2020-12: `type`, `format` (email/uri/date-time), `minimum`/`maximum`, `minLength`/`maxLength`, `pattern`, `required`, `enum`. Full conformance out of scope. |
    49→| `RuleParser` | `final class` | Static helper converting a rule string into a `RuleSet`. Splits on `\|`, parses each token into `[name, params]`, looks up the rule class in a static registry. Unknown names throw `UnknownRuleException` at parse time (fail-fast). |
    50→| `ValidationException` | `final class extends \RuntimeException` | Thrown by `ValidationResult::throw()` and controllers opting into throw-on-invalid. Carries the `ValidationResult`; CORE-08 catches and emits 422. |
    51→| `RequiredRule` | `final class extends Rule` | `passes()` returns `!empty($value)` (`0`/`'0'` are non-empty per PHP). Message: `'{field} is required'`. |
    52→| `EmailRule` | `final class extends Rule` | `passes()` returns `filter_var($value, FILTER_VALIDATE_EMAIL) !== false`. Empty values short-circuit to `true` (combine with `RequiredRule` to forbid empties). Message: `'{field} must be a valid email address'`. |
    53→| `MinLengthRule` | `final class extends Rule` | Constructor: `int $min`, `bool $multibyte = false`. `passes()` returns `strlen($value) >= $this->min` (or `mb_strlen` when multibyte). Non-strings return `false`. Message: `'{field} must be at least {min} characters'`. |
    54→| `UniqueRule` | `final class extends Rule` | Constructor: `string $table`, `string $column`, CORE-19 `ConnectionInterface`, `?string $exceptColumn`, `mixed $exceptValue`. `passes()` issues parameterised `SELECT EXISTS(SELECT 1 FROM <table> WHERE <column> = ? [AND <exceptColumn> <> ?])`. Returns `false` if exists; `true` if `exceptValue` matches (update flow). DBAL failures caught, logged, treated as fail-closed (`false`) — a DB outage must never silently approve a uniqueness check. Message: `'{field} has already been taken'`. |
    55→| `RegexRule` | `final class extends Rule` | Constructor: `string $pattern` (delimiters + modifiers). `passes()` returns `preg_match($this->pattern, $value) === 1`. Invalid regex throws `InvalidArgumentException` at construction. Message: `'{field} has an invalid format'` — generic, never echoes the pattern. |

    57→### Interface Contracts
    58→
    59→```php
    60→<?php
    61→declare(strict_types=1);
    62→
    63→namespace SovereignStack\Hub\Validation;
    64→
    65→/**
    66→ * Main entry point for declarative input validation.
    67→ *
    68→ * A Validator owns an optional CORE-19 ConnectionInterface (required by
    69→ * DB-touching rules like UniqueRule), an optional PSR-3 LoggerInterface
    70→ * for fail-closed diagnostics, and an optional HUB-13 TranslatorInterface.
    71→ *
    72→ * validate() is pure: it never throws on invalid data. It returns a
    73→ * ValidationResult that the caller inspects (->isValid()) or throws
    74→ * (->throw()). The only exceptions validate() raises are infrastructure
    75→ * failures (malformed rule string, max-depth exceeded) — never "the data
    76→ * was invalid".
    77→ *
    78→ * The $rules array maps a dot-path field name to either a string
    79→ * ('required|email|unique:users,email') or an array of RuleInterface.
    80→ * Dot-paths support nested data: 'user.profile.email' resolves
    81→ * $data['user']['profile']['email']. Maximum nesting depth is enforced
    82→ * (default 8) to prevent deeply-nested payload DoS.
    83→ */
    84→interface ValidatorInterface
    85→{
    86→    /**
    87→     * Validate $data against $rules.
    88→     *
    89→     * @param array<string, mixed> $data   Input data, typically
    90→     *        $request->getParsedBody() or getQueryParams().
    91→     * @param array<string, string|array<int, RuleInterface>> $rules
    92→     *        Dot-path field name → rule string or rule-instance array.
    93→     *
    94→     * @return ValidationResult Collects every ValidationError across every
    95→     *         field. Never throws on invalid data.
    96→     *
    97→     * @throws UnknownRuleException       If a rule string references an unregistered name.
    98→     * @throws MaxDepthExceededException  If $data nesting exceeds the configured maximum.
    99→     * @throws \InvalidArgumentException If a rule's constructor parameters are malformed.
   100→     */
   101→    public function validate(array $data, array $rules): ValidationResult;
   102→}
   103→
   104→/**
   105→ * Contract for a single validation rule.
   106→ *
   107→ * A rule is stateless with respect to the field it validates: the same
   108→ * rule instance may be reused across multiple validate() calls. State
   109→ * that varies per call (e.g., the table.column for UniqueRule) is set at
   110→ * construction time.
   111→ *
   112→ * passes() receives the full $data array, not just the single field value,
   113→ * so cross-field rules (e.g., "password_confirmation must equal password")
   114→ * are first-class: the rule can read $data['password'] to validate
   115→ * $data['password_confirmation'].
   116→ *
   117→ * The $value parameter is mixed because validation often runs before the
   118→ * value's type is asserted — a RequiredRule must accept null, an
   119→ * EmailRule must accept non-strings (returning false), and a MinLengthRule
   120→ * must accept arrays (returning false, not throwing).
   121→ */
   122→interface RuleInterface
   123→{
   124→    /**
   125→     * Returns true if $value passes this rule, false otherwise.
   126→     *
   127→     * Implementations MUST NOT throw on type mismatches; they MUST return
   128→     * false. Throwing is reserved for infrastructure failures (DBAL down
   129→     * in UniqueRule, etc.) which the Validator catches and converts to
   130→     * fail-closed false.
   131→     *
   132→     * @param mixed                 $value The value at the field's dot-path in $data.
   133→     * @param array<string, mixed>  $data  The full input data array, for cross-field rules.
   134→     */
   135→    public function passes(mixed $value, array $data): bool;
   136→
   137→    /**
   138→     * Returns the human-readable error message template for a failed pass.
   139→     *
   140→     * The Validator interpolates the template with the field name and the
   141→     * rule's own parameters. The message MUST NOT include the database
   142→     * column name (use the field name), the regex pattern (use "invalid
   143→     * format"), or the actual submitted value (never echo user input back).
   144→     * The message MAY include placeholders ({field}, {min}, {max}, etc.).
   145→     */
   146→    public function message(): string;
   147→}
   148→```

   150→### Reference Implementation
   151→
   152→```php
   153→<?php
   154→declare(strict_types=1);
   155→
   156→namespace SovereignStack\Hub\Validation;
   157→
   158→use SovereignStack\Core\Database\ConnectionInterface;
   159→use Psr\Log\LoggerInterface;
   160→use Psr\Log\NullLogger;
   161→
   162→/**
   163→ * Concrete Validator. Autowired via CORE-02 with CORE-19 ConnectionInterface
   164→ * (for UniqueRule), PSR-3 LoggerInterface (defaults to NullLogger), and an
   165→ * int $maxDepth DoS guard (default 8).
   166→ *
   167→ * Usage:
   168→ *   $result = $validator->validate($request->getParsedBody(), [
   169→ *       'email'    => 'required|email|unique:users,email,id,' . $user->id,
   170→ *       'password' => 'required|min:8|regex:/^(?=.*[A-Z])(?=.*[0-9]).{8,}$/',
   171→ *   ]);
   172→ *   $result->throw();  // throws ValidationException iff invalid
   173→ */
   174→final class Validator implements ValidatorInterface
   175→{
   176→    private readonly LoggerInterface $logger;
   177→
   178→    public function __construct(
   179→        private readonly ?ConnectionInterface $connection = null,
   180→        ?LoggerInterface $logger = null,
   181→        private readonly int $maxDepth = 8,
   182→    ) {
   183→        $this->logger = $logger ?? new NullLogger();
   184→    }
   185→
   186→    public function validate(array $data, array $rules): ValidationResult
   187→    {
   188→        $this->assertDepth($data, 0);
   189→
   190→        $errors = [];
   191→
   192→        foreach ($rules as $field => $ruleSpec) {
   193→            $ruleSet = is_string($ruleSpec)
   194→                ? RuleParser::parse($ruleSpec, $this->connection, $this->logger)
   195→                : new RuleSet($ruleSpec);
   196→
   197→            $value = $this->resolve($data, $field);
   198→
   199→            $fieldErrors = $ruleSet->execute($value, $data);
   200→            foreach ($fieldErrors as $error) {
   201→                $errors[] = new ValidationError(
   202→                    field: $field,
   203→                    rule: $error->rule,
   204→                    message: $this->interpolate($error->message, $field, $error->params),
   205→                );
   206→            }
   207→        }
   208→
   209→        return new ValidationResult($errors);
   210→    }
   211→
   212→    /**
   213→     * Resolve a dot-path field name to its value in $data.
   214→     * Returns null if any intermediate key is missing.
   215→     */
   216→    private function resolve(array $data, string $field): mixed
   217→    {
   218→        $current = $data;
   219→        foreach (explode('.', $field) as $segment) {
   220→            if (!is_array($current) || !array_key_exists($segment, $current)) {
   221→                return null;
   222→            }
   223→            $current = $current[$segment];
   224→        }
   225→        return $current;
   226→    }
   227→
   228→    /**
   229→     * Reject payloads deeper than $this->maxDepth (DoS guard).
   230→     */
   231→    private function assertDepth(mixed $data, int $depth): void
   232→    {
   233→        if ($depth > $this->maxDepth) {
   234→            throw new MaxDepthExceededException(
   235→                "Input data exceeds maximum nesting depth of {$this->maxDepth}"
   236→            );
   237→        }
   238→        if (is_array($data)) {
   239→            foreach ($data as $value) {
   240→                $this->assertDepth($value, $depth + 1);
   241→            }
   242→        }
   243→    }
   244→
   245→    private function interpolate(string $template, string $field, array $params): string
   246→    {
   247→        $params['{field}'] = $field;
   248→        return strtr($template, $params);
   249→    }
   250→}
   251→
   252→/**
   253→ * Concrete RequiredRule. passes() returns true for any non-empty value
   254→ * (0 and '0' are non-empty per PHP semantics).
   255→ */
   256→final class RequiredRule extends Rule
   257→{
   258→    protected string $template = '{field} is required';
   259→
   260→    public function passes(mixed $value, array $data): bool
   261→    {
   262→        return !empty($value);
   263→    }
   264→}
   265→
   266→/**
   267→ * Concrete EmailRule. Empty values short-circuit to true (combine with
   268→ * RequiredRule to forbid empties). Non-strings return false.
   269→ */
   270→final class EmailRule extends Rule
   271→{
   272→    protected string $template = '{field} must be a valid email address';
   273→
   274→    public function passes(mixed $value, array $data): bool
   275→    {
   276→        if (!is_string($value) || $value === '') {
   277→            return true;
   278→        }
   279→        return filter_var($value, FILTER_VALIDATE_EMAIL) !== false;
   280→    }
   281→}
   282→
   283→/**
   284→ * Concrete MinLengthRule. $multibyte switches between strlen and mb_strlen.
   285→ */
   286→final class MinLengthRule extends Rule
   287→{
   288→    protected string $template = '{field} must be at least {min} characters';
   289→
   290→    public function __construct(
   291→        private readonly int $min,
   292→        private readonly bool $multibyte = false,
   293→    ) {}
   294→
   295→    public function passes(mixed $value, array $data): bool
   296→    {
   297→        if (!is_string($value)) {
   298→            return false;
   299→        }
   300→        $length = $this->multibyte ? mb_strlen($value) : strlen($value);
   301→        return $length >= $this->min;
   302→    }
   303→
   304→    protected function params(): array
   305→    {
   306→        return ['{min}' => (string) $this->min];
   307→    }
   308→}
   309→
   310→/**
   311→ * Concrete UniqueRule. Issues a parameterised SELECT EXISTS(...) via CORE-19.
   312→ * Supports an optional except clause for update flows:
   313→ *   unique:users,email,id,42
   314→ *   → SELECT EXISTS(SELECT 1 FROM users WHERE email = ? AND id <> ?)
   315→ *
   316→ * DBAL failures are caught, logged, and treated as fail-closed (false).
   317→ * A database outage must never silently approve a uniqueness check.
   318→ */
   319→final class UniqueRule extends Rule
   320→{
   321→    protected string $template = '{field} has already been taken';
   322→
   323→    public function __construct(
   324→        private readonly string $table,
   325→        private readonly string $column,
   326→        private readonly ?ConnectionInterface $connection,
   327→        private readonly ?string $exceptColumn = null,
   328→        private readonly mixed $exceptValue = null,
   329→        private readonly LoggerInterface $logger = new NullLogger(),
   330→    ) {
   331→        if ($this->connection === null) {
   332→            throw new \InvalidArgumentException(
   333→                'UniqueRule requires a CORE-19 ConnectionInterface; none was provided.'
   334→            );
   335→        }
   336→    }
   337→
   338→    public function passes(mixed $value, array $data): bool
   339→    {
   340→        if (!is_scalar($value) || $value === '') {
   341→            return true; // empty values skip uniqueness; use RequiredRule
   342→        }
   343→
   344→        $sql = "SELECT EXISTS(SELECT 1 FROM {$this->table} WHERE {$this->column} = ?";
   345→        $bindings = [$value];
   346→
   347→        if ($this->exceptColumn !== null) {
   348→            $sql .= " AND {$this->exceptColumn} <> ?";
   349→            $bindings[] = $this->exceptValue;
   350→        }
   351→        $sql .= ")";
   352→
   353→        try {
   354→            $result = $this->connection->fetchOne($sql, $bindings);
   355→            return !$result; // EXISTS returns 1 if a row matches → not unique → false
   356→        } catch (\Throwable $e) {
   357→            $this->logger->warning(
   358→                'UniqueRule DBAL failure; failing closed',
   359→                ['table' => $this->table, 'column' => $this->column, 'exception' => $e]
   360→            );
   361→            return false; // fail closed
   362→        }
   363→    }
   364→}
   365→
   366→/**
   367→ * Concrete RegexRule. Pattern includes delimiters and modifiers.
   368→ * Invalid regex throws InvalidArgumentException at construction time.
   369→ */
   370→final class RegexRule extends Rule
   371→{
   372→    protected string $template = '{field} has an invalid format';
   373→
   374→    public function __construct(
   375→        private readonly string $pattern,
   376→    ) {
   377→        if (@preg_match($pattern, '') === false) {
   378→            throw new \InvalidArgumentException("Invalid regex pattern: {$pattern}");
   379→        }
   380→    }
   381→
   382→    public function passes(mixed $value, array $data): bool
   383→    {
   384→        if (!is_string($value) || $value === '') {
   385→            return true; // empty values skip format checks; use RequiredRule
   386→        }
   387→        return preg_match($this->pattern, $value) === 1;
   388→    }
   389→}

   392→### SQL DDL
   393→
   394→HUB-19 owns no persistent state — it has no tables. The `UniqueRule` issues a read-only `SELECT EXISTS(...)` against tables owned by other services (e.g., `users.email` is owned by HUB-04, `webhooks.endpoint_url` by HUB-17). The schema interaction pattern is documented here so downstream services know what columns must be queryable:
   395→
   396→```sql
   397→-- Any column referenced by a unique:<table>,<column> rule must exist,
   398→-- be indexed, and accept a parameterised equality predicate.
   399→--
   400→-- Example (HUB-04 Identity's users.email):
   401→--
   402→-- CREATE TABLE users (
   403→--     id    BIGSERIAL PRIMARY KEY,
   404→--     email VARCHAR(254) NOT NULL,
   405→--     CONSTRAINT users_email_unique UNIQUE (email)
   406→-- );
   407→-- CREATE UNIQUE INDEX users_email_idx ON users (lower(email));
   408→
   409→-- The UniqueRule's SQL template is parameterised (? placeholders bound
   410→-- via CORE-19's prepared-statement API):
   411→--   SELECT EXISTS(SELECT 1 FROM <table> WHERE <column> = ? [AND <exceptColumn> <> ?])
   412→-- The table and column names are interpolated at construction time from
   413→-- the controller's declarative rule string (source code, NOT request data).
   414→-- A CI lint asserts every <table>.<column> pair is present in a static
   415→-- allow-list, preventing dynamic table names from entering the SQL.
   416→```

   434→        V->>V: RuleParser::parse(ruleString) → RuleSet
   435→        V->>V: resolve($data, 'user.email') → value
   436→        V->>RS: execute(value, $data)
   437→        loop for each rule in RuleSet
   438→            RS->>R: passes(value, $data)
   439→            alt RequiredRule fails
   440→                R-->>RS: false
   441→                RS->>RS: short-circuit (skip remaining rules)
   442→                RS->>V: ValidationError(field, 'RequiredRule', msg)
   443→            else UniqueRule
   444→                R->>DB: SELECT EXISTS(... value, exceptValue ...)
   445→                DB-->>R: true (exists) / false (unique)
   446→                alt DBAL failure
   447→                    R->>R: log warning, fail closed → false
   448→                end
   449→                R-->>RS: !exists ? true : false
   450→                alt fails
   451→                    RS->>V: ValidationError(field, 'UniqueRule', msg)
   452→                end
   453→            else other rules
   454→                R-->>RS: bool
   455→                alt fails
   456→                    RS->>V: ValidationError(field, ruleName, msg)
   457→                end
   458→            end
   459→        end
   460→    end
   461→    V-->>C: ValidationResult(errors)
   462→    alt errors non-empty
   463→        C->>C: $result->throw()
   464→        Note over C: ValidationException raised
   465→        C-->>EH: throws ValidationException
   466→        EH->>EH: catch → format 422 body
   467→        EH-->>Client: HTTP 422 { "errors": { "user.email": ["..."], ... } }
   468→    else no errors
   469→        C->>C: proceed with handler logic
   470→        C-->>Client: HTTP 200 / 201
   471→    end
   472→```
   473→
   474→### State Diagram
   475→
   476→```mermaid
   477→stateDiagram-v2
   478→    [*] --> Pending: validate() invoked
   479→    Pending --> Validating: assertDepth passes, RuleParser builds RuleSets
   480→    Validating --> Valid: all rules pass for every field
   481→    Validating --> Invalid: one or more rules fail
   482→    Invalid --> [*]: ValidationResult.errors() returned; controller calls throw() → ValidationException → 422
   483→    Valid --> [*]: ValidationResult.isValid() === true; controller proceeds
   484→
   485→    Pending --> Rejected: depth exceeds maxDepth (MaxDepthExceededException)
   486→    Pending --> Rejected: unknown rule name (UnknownRuleException)
   487→    Rejected --> [*]: infrastructure failure, not a validation failure
   488→```

   490→## Integration Strategy
   491→
   492→**Upward (consumed by HUB-19):**
   493→- **CORE-02** (DI Container) autowires `Validator` into every controller constructor. The CORE-19 `ConnectionInterface` and optional PSR-3 `LoggerInterface` are injected by the container; `TenantContextInterface` (from HUB-04) is forwarded to `UniqueRule` when tenant-scoped uniqueness is required (`unique:tenants_users,email,tenant_id,<current_tenant>`).
   494→- **CORE-19** (DBAL) provides the parameterised `fetchOne()` method used by `UniqueRule`. The connection is shared across all rules in a single `validate()` call — no per-rule acquisition, no N+1.
   495→- **CORE-08** (Error Handler) catches `ValidationException` and emits 422. The handler is registered in CORE-18's boot phase; HUB-19's exception type is added to its 422-mapping table.
   496→- **CORE-09** (Logging) receives `warning`-level logs from `UniqueRule` on DBAL failure. The log entry contains table/column names (for operator diagnosis) but never the submitted value (no PII leakage to logs).
   497→- **HUB-13** (I18n, optional) translates the `{field} is required` templates; without HUB-13, English fallbacks are returned verbatim.
   498→
   499→**Downward (consumers of HUB-19):** Every Hub controller begins its handler with:
   500→```php
   501→public function register(ServerRequestInterface $request): ResponseInterface
   502→{
   503→    $result = $this->validator->validate($request->getParsedBody(), [
   504→        'email'    => 'required|email|unique:users,email',
   505→        'password' => 'required|min:8|regex:/^(?=.*[A-Z])(?=.*[0-9]).{8,}$/',
   506→        'name'     => 'required|min:2|max:80',
   507→    ]);
   508→    $result->throw();  // throws ValidationException on invalid input
   509→    // ... business logic ...
   510→}
   511→```
   512→BRIDGE-01 (Vanguard) validates cross-tier DTOs before forwarding; Spoke controllers use the same pattern via their `ServiceProvider` (CORE-17). The 422 response body is standardised across the stack:
   513→```json
   514→{ "errors": { "email": ["email must be a valid email address", "email has already been taken"],
   515→              "password": ["password must be at least 8 characters"] } }
   516→```
   517→This shape is part of the public API contract; changing it is SemVer-major.

   531→## CI Verification Criteria
   532→
   533→- **Branch coverage:** 100 % on `Validator::validate()` (depth-guard, dot-path resolver, string-vs-RuleInterface branches) and on each of the five rule classes' `passes()` methods, including `UniqueRule`'s DBAL-failure catch branch and `RegexRule`'s invalid-pattern constructor branch.
   534→- **Static analysis:** `phpstan` level 8 with `strictRules` and `bleedingEdge`; zero baseline-ignored errors. `psalm --taint-analysis` must report no taint flow from `$_GET`/`$_POST`/`$request->getParsedBody()` to `preg_match`, `preg_replace`, or SQL interpolation. (Note: `UniqueRule`'s table/column interpolation is from source-code rule strings, not user input — the taint config recognises this, asserted by the lint below.)
   535→- **Table/column allow-list lint:** Custom CI step scans every rule string for `unique:<table>,<column>` and asserts each pair is in `packages/hub/validation/allowed_unique_targets.php`. Prevents user-controlled table names from ever entering SQL.
   536→- **Required-field test:** `RequiredRuleTest` — missing field produces `ValidationError('field', 'RequiredRule', 'field is required')`; present-and-empty (`''`, `null`, `[]`) also errors; present-and-zero (`0`, `'0'`, `false`) does *not* error.
   537→- **Email-format test:** `EmailRuleTest` — `foo@bar.com` passes; `foo@bar` fails; `not-an-email` fails; empty string passes (defer to RequiredRule); non-string passes (defer to type-check rules).
   538→- **Unique test:** `UniqueRuleTest` — duplicate value errors; non-duplicate passes; existing-value-with-except passes (update flow); DBAL-outage stub returns `false` (fail-closed) and emits one `warning` log entry.
   539→- **Regex test:** `RegexRuleTest` — matching value passes; non-matching fails; empty passes; invalid pattern throws `InvalidArgumentException` at construction; the error message never contains the pattern itself.
   540→- **Nested-validation test:** `NestedValidationTest` — `user.profile.email` dot-path resolves through three levels; `tags.*.name` wildcard applies rule to each element of an array of objects; missing intermediate key produces a single "field is required" error, not a cascade.
   541→- **Max-depth test:** `MaxDepthTest` — depth-9 payload throws `MaxDepthExceededException` *before* any rule executes (so a malicious payload cannot trigger DB queries before rejection); depth-8 passes.
   542→- **End-to-end 422 test:** `ValidationExceptionTest` — controller calling `$result->throw()` on invalid input produces HTTP 422 with the standardised `{ "errors": { ... } }` body via CORE-08.
   543→- **Mutation testing:** `infection/infection` on the rule set; MSI ≥ 90 %. Targets: `!empty`→`empty` (Required), `!==`→`===` (Email), `>=`→`>` (MinLength), `<>`→`=` (Unique), `=== 1`→`=== 0` (Regex).

   545→## Security Properties
   546→
   547→1. **Defence in depth, enforced by convention.** No controller may read `$request->getParsedBody()` without first passing it through `Validator::validate()`. Enforced by a CI lint that greps for `getParsedBody()` calls not followed (within 5 lines) by a `->validate(` call, with an explicit allow-list for cases where validation is genuinely not needed (health-check endpoints with no body). Every byte of inbound request data is asserted against a declared rule set before it reaches a database write, templating engine, or downstream service.
   548→2. **Unique-rule queries are parameterised; table/column names are source-controlled.** `UniqueRule::passes()` uses CORE-19's `fetchOne($sql, $bindings)` API with `?` placeholders for the value and except-value. The `<table>` and `<column>` identifiers are interpolated into the SQL string at rule construction time but originate from the controller's declarative rule string (source code), not from request data. A CI lint asserts every `unique:<table>,<column>` pair matches a static allow-list. SQL injection at the validation layer is impossible by construction.
   549→3. **Error messages never leak internal schema.** `ValidationError::message` is a static template interpolated only with the field name (as declared by the caller) and the rule's own parameters. It never contains the database column name (uses `user.email`, not `users.email`), the regex pattern (uses "invalid format", not `/^[a-z]+$/i`), or the actual submitted value (never echoes user input back — prevents reflected-XSS-via-error-message and credential leakage via validation errors). `ErrorMessageLeakTest` asserts no error message contains `SELECT`, `FROM`, `column`, `table`, or `/`.
   550→4. **Validation rules are declarative and auditable.** The rule string `'required|email|unique:users,email'` is a single line of source code, statically parseable and subject to code review. There is no `Validator::addCustomRule()` runtime registration API — all rules are concrete classes in `SovereignStack\Hub\Validation\Rules`, registered in a static `RuleRegistry` at compile time. An auditor enumerates every validation rule with `grep -rn "unique:" blueprints/ src/` and verifies each. Hidden validation logic (e.g., conditionally skipping a rule based on a runtime flag) is forbidden by the CI lint.
   551→5. **Max input depth enforced; deeply-nested payload DoS rejected.** `Validator::validate()` walks `$data` to depth `$this->maxDepth` (default 8) before executing any rule. A depth-9 payload throws `MaxDepthExceededException` and is rejected with HTTP 400 — *before* any rule executes, *before* any DB query is issued. This prevents an attacker from submitting `{"a":{"a":{"a":...}}}` × 10 000 to consume CPU in rule iteration or trigger N+1 DB queries via a wildcard `tags.*` rule. The limit is configurable per `Validator` instance (e.g., a webhook receiver expecting depth-10 payloads can raise it to 12); the default is conservative.

   554→
   555→**Landing plan (per `01_MASTER_INDEX.md` §5 build sequence, Step 8):**
   556→
   557→1. After CORE-02 (Step 1) and CORE-19 (Step 5) land, create `packages/hub/validation/` with `composer.json` declaring `php:^8.3`, `psr/log:^3.0` (optional), and `sovereign-stack/core-database:*` (required for `UniqueRule`).
   558→2. Implement the six core classes, two interfaces, and five built-in rules per the Reference Implementation.
   559→3. Wire into CORE-17's `ServiceProvider` system: `ValidationServiceProvider` registers `ValidatorInterface` as a singleton alias of `Validator`, autowired with `ConnectionInterface` and `LoggerInterface`.
   560→4. Register `ValidationException` in CORE-08's error-handler mapping table (exception class → HTTP 422 + JSON body shape).
   561→5. Migrate the first controller (HUB-04 Identity's `register` endpoint) to `Validator::validate()`; observe the 422 response shape in CI; remove the controller's hand-rolled validation block.
   562→6. Migrate remaining Hub controllers in criticality order (HUB-01, HUB-06, HUB-08, HUB-17, HUB-20, then the rest), then Spoke controllers. Each migration is a single PR; the CI lint refuses to merge any controller that reads `getParsedBody()` without a `validate()` call.
   563→7. After all controllers migrate, delete the `SOLUTIONS_TO_WEAKNESSES.md` entry for "Validation Engine" (per Governance Rule 5).
   564→
   565→**Rollback procedure:**
   566→
   567→- **Package-level rollback** (HUB-19 deemed unfit for production): `composer remove sovereign-stack/hub-validation`. Every controller that called `$this->validator->validate(...)` must revert to its hand-rolled validation block — a regression in consistency (each controller re-implements email-format and uniqueness checks with no central audit surface) and a likely regression in security (hand-rolled uniqueness checks are the historical source of SQL injection at the validation layer). High-cost; the better path is to fix HUB-19 in place.
   568→- **Per-controller rollback** (a single controller's rule set is wrong): revert that controller's PR; `Validator` and rule classes remain for other controllers. Low-cost, no blast radius outside the reverted controller.
   569→- **`UniqueRule`-only rollback** (DBAL integration is unstable): gate `UniqueRule` behind a feature flag (`hub_validation_unique_enabled`). When disabled, `RuleParser` throws `UnknownRuleException` on any `unique:` token, forcing the caller to handle the absence explicitly (no silent fall-through to "no uniqueness check"). Safest partial rollback — preserves every other rule's behaviour while disabling only the DB-touching rule.
   570→
   571→**Forward-compatibility hooks:**
   572→
   573→- `RuleInterface` is extensible: future rules (`ExistsRule`, `InRule`, `NotInRule`, `ConfirmedRule`, `DateRule`) are added as new classes registered in the static `RuleRegistry`; no interface change is required, so the addition is SemVer-minor.
   574→- `RuleSet::execute()` is the integration point for future async rules (e.g., a rule calling an external API to verify a phone number). The current contract is synchronous (`passes(): bool`); an `AsyncRuleInterface` extending `RuleInterface` may be added in a future major version without breaking existing rules.
   575→- `SchemaValidator` is intentionally a subset of JSON Schema draft-2020-12. Full conformance (`$ref`, `oneOf`/`anyOf`/`allOf`, conditional `if`/`then`/`else`) is a future major version; the current subset is sufficient for OpenAPI request-body validation.

   578→
   579→**Minor** when first landed (1.0 → 1.1). The package is new; no existing API changes. Controllers adopt `Validator::validate()` incrementally; the 422 response body shape is part of the public API contract from day one.

   581→**Major** (1.x → 2.0) triggers:
   582→- Removal of any rule class from the `Rules` namespace (preceded by `@deprecated` + parallel new class for one minor cycle).
   583→- Change to `ValidatorInterface::validate()` signature (e.g., adding a third parameter without a default).
   584→- Change to `RuleInterface::passes()` signature.
   585→- Change to `ValidationResult::toArray()` shape (JSON consumed by frontends).
   586→- Change to the 422 response body shape (e.g., moving from `{ "errors": { ... } }` to RFC 7807 `application/problem+json`).
   587→- Change to the default `maxDepth` (lower could break legitimate deep payloads; higher weakens the DoS guard).

   589→**Patch** for: bug fixes, internal refactors preserving all public signatures, new translations (HUB-13 message keys), and `phpstan`/`psalm` baseline cleanups.
