    25→## §0. Authority Boundary (per ADR-021 §11)
    26→
    27→> **INDEX is the canonical registry of architectural identity and governance, while dependency graphs are generated authoritative views of declared intent and verified implementation state.**
    28→

    30→- IDs, names, tier membership, numbering
    31→- Canonical status (Accepted / Proposed / Superseded)
    32→- ADR relationships
    33→- Governance rules
    34→
    35→**INDEX does NOT own (generated, not manually maintained):**
    36→- Actual Composer dependencies (use Verified DAG)
    37→- Actual namespace imports (use Verified DAG)
    38→- Actual implementation status (use generated baseline)
    39→- Actual topological ordering (use generated build order)
    40→- Actual test state (use CI)

    42→**Derived facts are generated from repository evidence, not hand-maintained in INDEX.** This prevents the documentation drift that occurred when INDEX manually maintained implementation counts that diverged from the actual repository state.

   273→### §5.1 Edge-direction convention (binding)
   274→
   275→Every blueprint's `Dependency Status` section uses these two words with exactly these meanings — the
   276→same meanings as `AUTHORING_GUIDE.md`:
   277→
   278→- **Upward** — the IDs **this component consumes**.
   279→- **Downward** — the IDs that **consume this component**.
   280→
   281→A pair of components that each list the other as *Downward* is a **cycle** and a broken build, even if
   282→the intent was harmless. `Verification/lint/run.php` detects mutual-downward pairs. Two such pairs

   287→never appear in a Core blueprint's *Upward* list; `CORE-01` is upstream of `DEPLOY-01`, never the

   473→## §7. Governance rules
   474→
   475→Binding on all contributions. `Verification/lint/run.php` enforces the mechanical subset.
   476→
   477→**Rule 1 — One numbering authority.** §2 is the only place a Core/Hub/Spoke/Bridge/Deploy ID's identity
   478→is defined. A blueprint that changes a component's ID, name, or scope must update §2 in the same
   479→commit. A blueprint and this index disagreeing is a **broken build**.
   480→
   481→**Rule 2 — No performance target without a method.** Every performance target must name its
   482→**harness** (e.g. PHPUnit `--group performance`, `wrk`, `k6`), its **baseline** (hardware/runtime,
   483→e.g. GitHub Actions `ubuntu-latest`, PHP 8.3, opcache on, Xdebug off), and its **load model**
   484→(concurrency, request mix, dataset size). A target that cannot meet this bar must be written
   485→**"provisional, unverified"**. Bare millisecond claims are forbidden (Finding 10).
   486→
   487→**Rule 3 — Evaluation docs are dated snapshots.** Any evaluation document must carry
   488→`Valid as of commit <sha>. Do not use for planning without re-verification.` The archived
   489→`docs/evaluation/` tree is valid as of an unknown pre-renumbering commit and must not be used
   490→(Finding 2).
   491→
   492→**Rule 4 — Rejections need a real reason.** A `disapproved/` entry must state specifically what was
   493→rejected and why. The single boilerplate line *"Varying from the original blueprints"* covering 74
   494→files is insufficient (Finding 12).
   495→
   496→**Rule 5 — Solutions must land in the artefact, not beside it.** A weakness write-up is not resolved
   497→until the referenced blueprint file is edited (Finding 11).
   498→
   499→**Rule 6 — Duplicate directories require a diff check.** Nothing named `*_Optimized`, `*_v2`,
   500→`*_mobile`, or similar may be committed without CI verifying it is not byte-identical (or within a 5%
   501→size delta) to its source (Findings 5, 18).
   502→
   503→**Rule 7 — Blueprint fidelity bar.** See `AUTHORING_GUIDE.md`. Placeholder and stub blueprints are
   504→explicitly exempt and must say so in their first paragraph; everything else is gated.
   505→
   506→**Rule 8 — ADRs are required for non-obvious decisions.** Any decision with a viable alternative is
   507→recorded in `ADRs/` in Nygard format before the corresponding blueprint merges (Finding 19).
   508→
   509→**Rule 9 — Open questions are recorded, never silently resolved.** Any fork this consolidation could
   510→not close is in `OPEN-DECISIONS.md` with an owner and a decision route. Picking one silently is a
   511→governance violation.
